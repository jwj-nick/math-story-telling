### ★ 권장 = 문제 은행(JSON) 1회 추출 → 지면 생성


**한 번 추출해 두면 종이·오개념·재도전·나중의 앱이 전부 같은 소스에서 나온다.** 이게 이 작업의 레버리지다.

### 저작 메모

**KaTeX → HTML 변환이 이 단원 작업의 실체였다.** 63문항 전부 `$...$` 표기였고, 분수는 전부 CSS 세로분수로 옮겼다 — `$\dfrac{n(n-3)}{2}$` → `<span class="frac"><b>n(n−3)</b><i>2</i></span>`, `$\dfrac{360°}{n}$` → 같은 꼴. PDF 로 실제 렌더해 보니 **2단 좁은 칸에서도 세로분수가 깨지지 않았고**(유형 원리 상자·해설 본문 모두), 분자·분모가 한 줄씩 정상 배치됐다. `$\angle A$` → `∠A`, 빼기는 전부 U+2212(`−`) 로 통일했다.

**발문 규약에서 걸린 곳 — `고르시오` 는 요구문으로 인정되지 않는다.** V4 의 `DEMAND` 목록이 `하시오/구하시오/나타내시오/쓰시오` 라 `고르시오` 는 통과하지 못한다. 객관식 성격의 유형1-L1·M1 은 **"골라 번호와 이름을 쓰시오" · "모두 골라 기호를 쓰시오"** 로 바꿨는데, 결과적으로 종이에서 **답을 통째로 쓰게** 되어 규약 취지에도 맞았다.

**단위는 `answer_unit` 으로 빼고 `answer_print` 는 맨수로 뒀다.** 각도면 `"°"`, 개수면 `"개"`. 문제지 답란에 `답 ______ °` 처럼 단위가 미리 인쇄되고, 정답표에서도 `60 °` 로 나온다. 다만 답이 둘 이상이거나(`외각 120°, 내각 60°`) 서술이 섞이면(`90° (직각)`) 단위를 분리할 수 없어 `answer_unit: null` + `answer_format` 에 "도(°) 단위로" 를 명시하는 쪽으로 갔다.

**오개념 15개는 "숫자를 한 글자도 쓰지 않는" 제약 아래 썼다.** V5 는 `answer_print` 가 카드의 `empathy`/`counter`/`ask` 안에 **부분 문자열**로 들어 있으면 잡는데, 이 단원 정답은 `60`·`90`·`180`·`360` 같은 짧은 수치다. 카드에 `360°` 를 쓰는 순간 정답 `60` 이 그 안에 들어 있어 누출로 걸린다(`3-6-0`). 그래서 empathy·counter·ask 는 **전부 말로만** 썼다 — "외각의 합은 변의 수와 관계없이 늘 같아요" 가 아니라 아예 값을 말하지 않고 *"다각형 둘레를 한 바퀴 걸으며 꼭짓점마다 몸을 튼다면, 제자리로 돌아왔을 때 몇 바퀴를 돈 셈인가요?"* 로. 숫자는 leak 검사를 받지 않는 `check` 에만 넣었다. **제약이 카드를 설명에서 반례로 밀어낸 셈**이라 결과가 더 나았다.

**핵심 오개념 = 4번 「대각선 공식에서 ÷2 를 빠뜨림」과 12번 「외각의 합이 변의 수에 따라 달라진다고 봄」.** 4번은 유형2 전체(9문항 중 8문항)에 걸리고, 12번은 유형5의 축이다. 짝이 되는 5번(한 꼭짓점 대각선 ↔ 전체 대각선)과 10번(내각의 합 −2 누락)을 옆에 세워, "무엇을 세고 있는가"를 카드끼리 마주 보게 배치했다.

**`figure_svg` 는 손대지 않고 그대로 실었다.** 다만 유형7-M1 오각별 SVG 는 원본 자체에 결함이 있다 — 끝점 라벨 `c`·`d` 의 `y` 가 252·262 인데 `viewBox` 높이가 260 이라 **인쇄에서 아래쪽이 살짝 잘린다.** 또 `<text x="252,115" ...></text>` 라는 빈 요소(잘못된 x 속성)가 남아 있다. 지면 파이프라인이 아니라 **원본 앱 자산의 문제**이므로 여기서는 고치지 않았다. 고칠 때는 `type_07_app.html` 쪽을 손봐야 한다.

### 이 단원에서만 나온 것

**① 4지선다 63문항을 전부 단답형으로 재작성했다.** 중2의 2지선다와 달리 여기는 4지선다였는데, 종이에서는 여전히 찍기가 통한다. 보기를 통째로 걷어내고 발문만으로 답이 결정되게 고쳤다. 원본이 보기 대조에 기대던 문항 — 유형3-H2(`π를 약 1 단위로 처리해… 가로 6, 세로 8로 놓고 답하기` 라는 자기부정 지문), 유형6-M1·유형6-H2(`④ ② 또는 ③ 모두 같은 답`) — 은 **치수를 글로 주는 평서형 발문으로 다시 썼다.** 보기가 사라지니 원본의 군더더기도 같이 사라졌다.

**② π 방침을 못 박았다 — 전 문항 「π 를 남긴 꼴로」.** 원본 정답이 63문항 모두 `63π`·`\frac{256}{3}\pi` 처럼 π 형태였다. `answer_format` 에 `π 를 남긴 꼴로 (단위 cm³)` 를 넣었고, 유형7-H2(`216 − 24π`)만은 숫자와 π 가 섞여 오해가 크므로 **`π = 3.14 로 계산하지 않기`** 를 명시했다. 이게 갈리면 자기채점이 통째로 무너지는 단원이다.

**③ 단위가 이 단원의 생명이라 `answer_unit` 을 전부 채웠다.** 겉넓이 `cm²` · 부피 `cm³` · 길이 `cm` · 배수 `배` · 각도 `°`. 문제지 답란에 `답 ______ cm³` 로 미리 인쇄되고 정답표에도 따라붙는다. 원본 오답 보기에 **`③ 208 cm²` 처럼 수는 맞고 단위만 틀린 함정**이 실제로 있었는데, 단답형이 되면서 그 함정이 "단위를 스스로 붙이는가" 로 옮겨 갔다. 답이 둘인 문항((1)겉넓이·(2)부피 등 4문항)만 `answer_unit: null` + 정답 안에 단위를 직접 넣었다.

**④ 세로분수와 √ 를 실제 렌더로 확인했다.** 유형6 은 `<span class="frac">` 이 발문·정답·해설에 모두 들어간다(`πh/3`, `12/5`, `9/5`, `16/5`, `256/3`, `176/3`, `48/5`). **2단 좁은 칸에서도 분자/분모가 정상 배치**됐다. 근호는 CDN 없이 `√<span style="text-decoration:overline">3</span>` 로 처리했고 정답표에서 윗줄까지 제대로 그어졌다(유형1-H1 `120 + 8√3`, 유형2-H3 `36√3`).

**⑤ 오개념 15개는 「기둥 2개 / 뿔 1개 / ×⅓ / 모선 vs 높이」 네 축으로 짰다.** 겉넓이 밑면 개수를 기둥(1번)·뿔(2번)로 갈라 마주 보게 두었고, 원뿔의 모선·높이 맞바꿈(5번)은 유형4 전체의 축이다. 단위 카드(8번)는 이 단원에서만 독립 카드로 세울 값어치가 있었다. 정답 누출 검사 때문에 `120`·`208` 같은 두 자리 이상 수치가 카드 본문에 들어가면 안 되므로 **empathy·counter·ask 는 전부 말과 손의 경험으로만** 썼다 — "기둥 모양 물통을 들고 위아래를 볼까요? 면이 몇 개 보이나요?" · "뿔에 물을 담아 기둥에 부으면 몇 번 만에 가득 찰까요?".

**⑥ SVG 가 0개인 단원이라 「보고 푸는」 문항이 하나도 없다.** 원본이 애초에 치수를 글로 주고 있어서 지면 이식에 그림 손실이 없었다. 대신 복합 입체·회전체는 글만으로 상황이 그려져야 해서, 유형6-M2(원기둥 위 원뿔)·유형6-H2(파낸 원기둥)는 **회전 결과의 반지름·높이를 발문에 직접 적어** 주었다. 계산이 여러 단계인 문항은 `work_space: lg` 로 올렸다(63문항 중 24문항).

## 중1 단원07 「기본도형」 프린트 학습지 — 완료

**결과:** 문항 63 (7유형 × 9) · 오개념 15 · 회차 9개(t1~t7 + mockA/mockB) · **PDF 18장** · 원본 SVG 5개(전부 이식).
`verify_bank.py` 결과 **오류 64 · 경고 52**. 오류는 **전부 이슈 1** 이고(V1 1건 + V2 63건), 발문·오개념·어투 검사(V4·V5·V6)는 **오류 0** 이다.

### 앞 단원들이 적어 둔 도구 이슈 3건, 여기서도 그대로 재현됐다

- **이슈 1 (V1/V2 idx 충돌)** — 확정. 세대 A `.q-num` 이 L·M·H 마다 1,2,3 으로 다시 시작해서 `re_extract` 의 `m[(t['no'], p['idx'])]` 가 63개를 **21개로 뭉갠다**. scratchpad 에서 `enumerate` 로 키를 만들어 대조하니 **63/63 원자 일치**. 은행은 원본과 어긋난 데가 없다.
- **이슈 2 (V3 vs V4 상충)** — 이 단원은 원자가 `$\overline{AM} = 6$ cm`·`$\angle AOC = 120°$` 처럼 **KaTeX 통째**로 들어온다. V4 가 `answer_print` 의 `$`·`\overline` 을 오류로 잡으니 규약을 지키는 한 V3 경고는 반드시 뜬다. 63문항 중 **52문항이 경고**이고, 나머지 11문항은 원자가 우리말·기호뿐이라 우연히 일치한 것이다(`(나), (라)`·`4종류`·`④ 꼬인 위치`·`한 점 (P) 에서 만남` 등).
- **이슈 3 (mock pick 레벨 혼합 불가)** — 의뢰는 "mockA = 7유형 × L·M 각 1", "mockB = M·H 각 1" 이었으나 `sorted(level) → [:per_type]` 구조상 **한 레벨만 뽑힌다**. config 는 의뢰대로 `per_type: 2` + `levels: ["L","M"]` / `["M","H"]` 로 두었고, 실제로 실린 것은 **mockA = L 14문항 · mockB = M 14문항**이다. H 는 유형 세트 t1~t7 에만 들어 있다.

### 이 단원에서만 나온 것

**① KaTeX 도형 기호를 전부 우리말로 옮겼다 — 이게 이 단원 작업의 실체였다.** `$\overline{AB}$`→`선분 AB` · `$\overrightarrow{AB}$`→`반직선 AB` · `$\overleftrightarrow{AB}$`→`직선 AB` · `$\angle AOB$`→`∠AOB` · `$l \parallel m$`→`두 직선 l, m 이 평행` · 빼기는 U+2212. **윗줄·화살표 기호를 흉내 내지 않고 말로 썼다.** 종이엔 툴팁이 없고, 세 표기의 차이를 아직 못 가르는 것이 유형1 의 학습 목표 그 자체여서 기호로 쓰면 문제가 문제를 가려 버린다. 발문·정답·힌트·해설 네 필드 모두 적용.

**② SVG 5개의 `<text>` 안에 KaTeX 리터럴이 살아 있었다.** `<text ...>$l$</text>`·`$m$`·`$x$` — 그대로 실으면 종이에 **`$l$` 이라고 인쇄된다**(앱에서는 KaTeX 가 지워 줬다). 도형 좌표·선·색은 하나도 건드리지 않고 **`$` 구분자만 걷어냈다.** 유형5 문제지 PDF 로 `l`·`m`·`x`·`130°`·`P` 가 정상 렌더되는 것까지 확인했다. 원본 앱 자산을 고친 것은 아니므로 `type_05_app.html` 은 그대로다.

**③ 원본 앱에 보기가 통째로 빠진 문항이 2개 있었다.** 유형1-M2(`다음 중 옳은 것은?`)·유형7-L2(`평행한 모서리는?`) 는 `.q-text` 에 보기가 없고 **`.sol-panel` 해설에만 ①~⑤ 가 등장한다.** 앱에서는 답을 눌러 확인하는 흐름이라 넘어갔겠지만 종이에서는 풀 수가 없다. 해설이 채점하고 있는 선택지를 그대로 복원해 발문에 실었다(유형1-M2 = 길이·방향·시작점·직선 유일성·선분 vs 반직선 5지선다, 유형7-L2 = `④ 위 셋 모두`). **원본 앱 쪽의 결함이므로 여기서는 지면만 고쳤다.**

**④ `고르시오` 는 V4 요구문 목록에 없다.** `DEMAND = [하시오, 구하시오, 나타내시오, 쓰시오]` 라서 선다형 7문항이 전부 "요구문 없음" 으로 걸렸다. `모두 골라 번호를 쓰시오`·`골라 기호를 쓰시오` 로 바꿔 해결했는데, 결과적으로 **답을 무엇으로 적어야 하는지가 발문에 드러나서 지면 규약(R3)에도 더 맞다.** 도구를 고칠 일이 아니라 발문을 고칠 일이었다.

**⑤ 각도·길이·개수는 `answer_unit` 으로 빼고 `answer_print` 는 수만 남겼다.** 문제지 답란에 `답 ______ °`·`______ cm`·`______ 개` 가 미리 인쇄된다(R4). 이 때문에 V3 경고가 늘지만, 종이에서 단위를 스스로 붙이게 하는 쪽이 값어치가 크다고 봤다. 답이 둘인 문항(`x = 25, 각의 크기 = 80°` 등 4문항)과 서술형 위치 관계 문항만 `answer_unit: null` 로 두고 정답 안에 단위를 넣었다.

**⑥ 오개념 15개는 「표기 / 길이 / 각 / 평행선 / 위치 관계」 다섯 축.** 단원이 7개 주제를 걸치는데 상한이 15라, 세기 오류는 `fig.count-lines` 로, 경우 빠뜨림은 `fig.between-add` 로, 이등분선은 `ang.split-add` 로 흡수했다. **정답 누출(V5) 때문에 empathy·counter·ask 에는 숫자를 한 자도 쓰지 않았고 점 이름도 P·Q·R 로 통일했다** — 이 단원은 `180`·`90`·`평행`·`직선 AB` 처럼 **답 자체가 개념어**여서, 카드가 개념을 설명하려 들면 그대로 답이 새기 때문이다. 그래서 카드 본문은 전부 손으로 그려 보게 하는 문장이 됐다 — "선분 PQ 와 선분 QP 를 각각 그려 볼까요? 그다음 반직선 PQ 와 반직선 QP 도 그려 봐요. 어느 쪽이 두 그림이 겹치나요?"

**⑦ 2단에서 도형이 칸을 넘지 않는지 눈으로 확인했다.** 유형5 문제지(SVG 4개)·mockB 해답묶음을 PDF 로 열어 봤다. 2단 배치·유형 머리말 붙음·정답표와 진단표 1단·오개념 카드 2단·표 머리행 페이지 넘김 반복·카드 정답 누출 없음까지 정상. `viewBox` 만 있고 `width` 가 없는 SVG 가 `max-width:100%` 로 칸 폭에 맞춰 축소됐다.

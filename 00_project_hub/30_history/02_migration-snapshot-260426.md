## 4. 새 세션에서 절대 잊지 말아야 할 5가지

이걸 어기면 프로젝트의 본질이 무너진다.

### (1) 우선순위는 명확하다
**(a) 흥미·이해·교양 > (c) AI 만드는 경험 > (b) 성적**
성적을 끌어올리려는 행동(과한 문제 풀이, 진도 강요)은 우선순위 위반.

### (2) "급하지 않다"는 명시적 합의
한 단원 약 2~3주, 한 학기 5~6단원이 페이스. 진도보다 깊이 우선.

### (3) 딸의 글쓰기는 임의 수정 금지
`her-writings/`에 들어갈 딸의 글은 본인 동의 없이 손대지 않는다.

### (4) 두 핵심 축을 모두 기억할 것
- 축 1: 인물 서사 기반 단원 학습 ("수학의 사람들")
- 축 2: 수학 언어 사용 설명서 ("Mathematical Literacy Track")
한쪽만 기억하면 절반의 프로젝트가 된다.

### (5) "어른 톤"으로 너무 정돈된 결과물 만들지 말 것
딸이 "내가 할 게 없다"고 느끼는 순간 동기 붕괴. **빈칸·미완성·질문을 의도적으로 남기는 게 설계**.

### 다음 갈래 (Claude Code 첫 작업 결정 필요)
이관 직후 사용자(아빠)가 결정할 사항:
- **길 A**: 단원 1 시범 제작
- **길 B**: L2 인터랙티브 도구 시범 제작
- **길 C**: A + B 병렬

웹 세션의 마지막 추천: **길 B → 길 A 순서**.
이유: L2가 딸 약점 정조준, 인터랙티브 도구가 첫 결과물로 인상 강함, 작은 도구가 큰 단원보다 시작 부담 적음.

## 6. Claude Code에서 작업할 때 팁 (사용자용)

### 첫 메시지 권장 형식
새 Claude Code 세션 시작 시 첫 메시지로:

```
이 프로젝트의 컨텍스트를 잡아줘. 다음 4개 파일을 순서대로 읽어:
1. README.md
2. docs/learner-profile.md
3. docs/concept.md
4. docs/literacy-track.md

읽은 후, 이 프로젝트의 (1) 우선순위, (2) 두 핵심 축, (3) 딸의 결정적 사례를 한 줄씩 확인해줘. 그다음 [작업할 내용]을 시작하자.
```

### 모델 선택 권장
- **계획·설계·연구**: Opus
- **단원 원고 작성**: Opus (창의력·서사 품질이 핵심)
- **인터랙티브 도구 코딩 (HTML+JS, React)**: Sonnet도 충분
- **반복적 수정·작은 편집**: Sonnet 또는 Haiku

### Skill 활용 권장
Claude Code에는 docx, pptx, xlsx, pdf, frontend-design 등 skill이 있다. 이 프로젝트에서는:
- **frontend-design**: L2 슬라이더 도구 같은 인터랙티브 결과물 만들 때
- **docx**: 나중에 단원 묶음을 인쇄용 문서로 만들 때 (선택)
- **나머지**: 거의 사용 안 함. 이 프로젝트는 마크다운 + HTML 중심.

### Git 운영 권장 (선택)
- repo 초기화는 사용자가 직접
- private 시작
- 커밋 단위: 단원 한 개 또는 의미 있는 마일스톤
- 딸이 PR 만들어보는 단계는 **3단계(딸 직접 채팅)** 시점에 도입 권장

## 7. 자주 발생할 함정과 회피법

### 함정 1: "결과물을 너무 잘 만들어버림"
새 Claude는 종종 어른 독자용 완성도 높은 문서를 만들려 함.
→ "이 결과물의 사용자는 중1, 수학 중하위, 글쓰기 강점, 감성적"이라는 점을 매번 상기.

### 함정 2: "교과서 진도대로 가려고 함"
새 Claude는 단원 1 → 2 → 3 순서로 가려는 경향이 있음.
→ 이 프로젝트는 **딸의 호기심**과 **학교 시험 일정**이 우선. 교과서 순서는 참고만.

### 함정 3: "축 2(수학 언어 트랙)를 잊어버림"
literacy-track.md를 안 읽으면 단원 학습만 만들어진다.
→ 위 Step 2의 4번 파일을 반드시 포함.

### 함정 4: "성적 향상 모드"
새 Claude가 학교 성적을 위해 문제 풀이 분량을 늘리려는 경향.
→ open-questions.md의 위험 요소 표 참고. "성적은 부수적"임을 재확인.

### 함정 5: "Adaptive Learning을 너무 일찍 도입"
새 Claude가 SM-2, IRT 같은 알고리즘을 일찍 제안할 수 있음.
→ 데이터 6개월 이상 쌓일 때까지 보류. open-questions.md의 보류 항목.

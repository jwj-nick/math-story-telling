## 0. 왜 종이인가

세은이는 앱에서 문제 푸는 것을 좋아하지 않는다. 그리고 종이에는 앱이 흉내 내기 어려운 것이 셋 있다.

1. **정답지가 물리적으로 다른 종이다.** "정답까지의 거리"가 공짜로 생긴다.
2. **풀이 공간이 곧 빈칸이다.** APP_PRINCIPLES 의 "빈칸을 남겨라"가 지면에서는 기본형이다.
3. **틀린 것만 다시 뽑을 수 있다.** 앱은 재출제해도 답을 기억하지만 종이는 새 종이면 된다.

## 1. 지면 기본

| 항목 | 값 |
|---|---|
| 용지 | A4 세로, **기본 2단** (문제집 편집) — 회차 config `"columns": 2` (기본) / `1` |
| 1단 전환 | 도형 그림이 크거나 표가 넓은 단원(중1 기하 등)은 `"columns": 1` 로 내린다 |
| 여백 | 위 14mm · 좌우 13mm · 아래 12mm |
| 본문 | 11pt, 행간 1.55, `Malgun Gothic` |
| 발문 | 11.5pt |
| 색 | **컬러 인쇄 전제.** 단 **색만으로 구분하지 않는다** — 흑백 복사 대비 |
| 난이도 | 색 + **기호 병기**: L `●○○` 기본 / M `●●○` 보통 / H `●●●` 도전 |
| 채점 기호 | **○ · △ · X** (유니코드 ✗ 대신 **X** — 폰트 폴백 편차 방지) |
| 문항 분리 | 문항 단위 `page-break-inside: avoid`. 유형 머리말은 **첫 문항까지 한 덩어리**(`.tgroup`) |

**수식 표기 = HTML `<sup>` + 유니코드.** KaTeX·MathJax 등 **CDN 의존을 두지 않는다.**
이유: 인쇄는 오프라인에서도 되어야 하고, headless 렌더가 외부 요청을 기다리면 안 된다.
분수는 CSS 세로분수, 근호는 `√` + `overline`, 도형은 인라인 SVG.

## 2. ★ 발문 규약 R1~R7

지면 문항은 앱 문항의 복사가 아니다. **응답 형식을 다시 짜야 한다.**
(앱 문항은 폰 입력에 맞춰 "숫자 빈칸 채우기"로 분해되어 있다. 종이에서는 답을 통째로 쓴다.)

**R1. 요구문을 명시한다.** `□`·빈칸에 기대지 않는다.
- ✗ `a³ × a⁴ = a□ 의 지수 □?`
- ✅ `a³ × a⁴ 을 간단히 하시오.`

**R2. 한 문항 = 한 요구.** 요구가 둘이면 (1)(2)로 나누고 답란도 나눈다.

**R3. 답의 형태를 지정한다.** — **자기채점이 무너지는 1순위 원인이 형태 모호함이다.**
- `a의 거듭제곱 꼴로` · `가장 간단한 식으로` · `기약분수로` · `x = 꼴로` · `소수 첫째 자리까지`
- 계산값과 거듭제곱 꼴이 갈리는 문항은 못 박는다: `2의 거듭제곱 꼴로 (계산한 수 32 아님)`
- 지수/계수 1 생략 규약도 밝힌다: `(지수 1 은 쓰지 않아요)`

**R4. 단위를 못 박는다.**
- 문제문에 단위 조건을 쓰고, **답란에 단위를 미리 인쇄한다** — `답 ________ cm²`
- 단위가 없으면 `answer_format` 에 `수로 (단위 없음)` 이라고 쓴다
- 단원 표준 단위: 각도 `°` · 길이 `cm` · 넓이 `cm²` · 부피 `cm³` · 개수 `개` · 확률 `기약분수`
- ⚠️ **`answer_unit`·`answer_format`·`answer_accept` 는 HTML 이스케이프된다.** 여기에 `cm<sup>2</sup>` 를 쓰면
  태그가 글자 그대로 인쇄된다 → **유니코드 `cm²`·`cm³` 를 쓴다.**
  (`stem_print`·`answer_print`·`hint`·`solution`·`principle`·오개념 카드 본문은 raw HTML 이라 `<sup>` 가 먹는다.)
- ⚠️ **단위를 두 번 쓰지 않는다.** 빌더는 정답표에 `answer_print` 뒤에 `answer_unit` 을 그대로 붙인다.
  답 문자열에 이미 단위를 넣고 `answer_unit` 까지 지정하면 **`7 cm cm`** 로 인쇄된다.
  → 길이·넓이·부피는 `answer_print` 에서 단위를 빼고 `answer_unit` 에만 쓴다.
  → 각도처럼 숫자에 붙여 써야 자연스러운 것(`40°`)은 `answer_print` 에 두고 `answer_unit: null` + `answer_format` 에 `(단위 °)` 를 명시한다 (`40 °` 로 벌어지는 것을 피한다).

**R5. 앱 의존 표현 금지.** `버튼`, `슬라이더`, `눌러`, `탭`, `위 그림에서 값을 바꿔` → 전부 제거.

**R6. 그림은 문항 옆에 인쇄한다.** 인라인 SVG. 그림이 다음 장으로 넘어가면 안 된다.

**R8. 유형 원리 상자는 답을 주지 않는다.**
문제지 맨 위의 `principle` 은 **푸는 방법**을 알려 주는 자리이지 답을 알려 주는 자리가 아니다.
실측 사례: 「대각선이 수직인 사각형은 마름모」라고 써 두면, 그 유형의 문항 두 개가 답이 `마름모` 라 그대로 새어 나간다.
→ **판별 방법**(`대각선이 어떤 성질을 갖는지 보고 이름을 정해요`)으로 바꿔 쓴다.
같은 이유로 오개념 카드 본문에 **정답 낱말·숫자를 쓰지 않는다** — 정답이 `80` 이면 카드에 `180` 만 써도 누출로 잡힌다.

**R7. 어투.** `WRITING_VOICE.md` 준수.
- **안내문·오개념 카드·격려문 = 해요체** ("풀어 보고", "괜찮아요")
- **발문 자체 = 시험 문투 허용** ("구하시오", "간단히 하시오") — 실제 시험지와 형식을 맞춘다
- 유형 원리 상자는 학생에게 보이는 안내문이므로 **해요체** ("지수를 더해요", ✗ "더한다")

## 3. 산출물 — **회차당 2파일** (양면 인쇄 절약)

**푼 뒤에 보는 것(정답·진단표·오개념카드·해설)은 전부 한 파일 `K` 로 합친다.**
따로 뽑으면 반쪽짜리 종이가 여러 장 남는다.

| 기호 | 산출물 | 구성 |
|---|---|---|
| **Q** | 문제지 | 머리말 · 이름/날짜 · 목표시간/문항수 · 채점 안내 · 유형 원리 상자 · 문항(번호·난이도·발문·답의 형태·**풀이 공간**·답란) |
| **K** | **해답 묶음** | ① 정답 표(번호 / 정답 / **이렇게 써도 맞아요** / **X 일 때 볼 카드 번호**) → ② 오답 진단표(○ △ X · 카드 번호 · 다시 푼 날 + 오개념 빈도표) → ③ 오개념 카드(6요소 + 확인 문제 정답 한 줄) → ④ 해설(힌트 + 단계별 풀이) |
| (R) | 재도전지 | 진단표에서 나온 오개념 태그에 걸린 문항만 재출제 |

**K 안의 단 구성 — 표는 1단, 나머지는 2단.**

| 절 | 단 | 이유 |
|---|---|---|
| ① 정답 표 · ② 진단표 | **1단** | 표는 열 폭이 필요하고, 진단표는 손으로 채운다 |
| ③ 오개념 카드 · ④ 해설 | **2단** | 읽기만 하는 글 → 2단이 종이를 아낀다 |

- **표는 `<thead>` 를 쓴다** — 페이지가 넘어가도 머리행이 반복된다
- **K 안에서 각 절의 안내문을 반복하지 않는다.** 채점 규약은 맨 위 한 번만
- 분리본이 필요하면 `outputs` 에 `A`/`S`/`D`/`M` 을 직접 넣는다 (빌더는 그대로 있다)

**Q 와 K 는 반드시 별개 파일이다.** 같은 종이에 실으면 §0-1 이 무너진다.

**풀이 공간 높이** — 난이도별로 다르게. 좁으면 안 쓰고, 넓으면 장수만 는다.

| `work_space` | 1단 | **2단(기본)** | 대상 |
|---|---|---|---|
| `sm` | 24mm | 21mm | L (한 줄 계산) |
| `md` | 34mm | 29mm | M |
| `lg` | 48mm | 41mm | H (여러 단계) |

## 5. 자기채점 규약

**채점 주체 = 학생 본인.** 다음 3단계가 이 설계의 핵심이다.

| 기호 | 뜻 | 다음 행동 |
|---|---|---|
| **○** | 맞음 | 넘어간다 |
| **△** | 틀렸지만 **어디서 틀렸는지 알겠음** (계산 실수 등) | 그 자리에서 다시 푼다. **오개념 아님** |
| **X** | **왜 틀렸는지 모르겠음** / 손도 못 댐 | **오개념 카드**를 읽고 진단표에 카드 번호를 적는다 |

- **점수는 기록하지 않는다.** 남이 지적하는 게 아니라 자기 패턴을 자기가 본다
- 동치 표현은 정답지 **"이렇게 써도 맞아요"** 칸에 미리 인쇄한다 (`answer_accept`)
- 정답지·해설지는 문제를 **다 푼 뒤에** 꺼낸다

## 6. 회차 두 종류

| 형 | `kind` | 구성 | 용도 |
|---|---|---|---|
| **ㄱ 유형 세트** | `type-set` | 한 유형 또는 이웃 유형 2~3개를 묶어 9~12문항 | **평소 연습** (중2 = 현재 진도) |
| **ㄴ 모의 회차** | `mock` | 여러 유형에서 뽑아 섞고 **난이도 오름차순** 12~16문항 + 목표시간 | **시험 대비** (중1 2학기) |

`mock` 은 유형 머리말·원리 상자를 인쇄하지 않는다 (시험처럼).

## 8. 도구 사용 시 걸리는 함정 (실측 기록)

1. **PowerShell 5.1 은 `.ps1` 을 ANSI(cp949)로 읽는다.** BOM 없는 UTF-8 파일에 한글을 넣으면 파서가 깨진다.
   → `print_pdf.ps1` 은 **ASCII 전용**. 한글 파일명은 `build_sheet.py` 가 계산해 `_pdfplan.json` 으로 넘긴다.
2. **headless Chrome 은 새 프로필로 뜨면 외부와 통신하다 멈춘다** (GCM 등록·sync·component update).
   PDF 는 이미 써 놓고도 프로세스가 안 끝난다. → `--disable-background-networking --disable-sync
   --disable-component-update` 등으로 막고, **`WaitForExit(90초)` 후 강제 종료**한다.
3. **Python 실행 전 `PYTHONIOENCODING=utf-8`** 을 선제 설정한다 (cp949 stdout 충돌).
4. 중첩 PowerShell 호출은 **`-NoProfile`** 을 붙인다 (사용자 프로필 오류가 섞여 들어온다).
5. ★ **결합 문자(combining diacritic)는 인쇄되지 않는다.** 순환소수 점 `U+0307` 은 화면에서는 숫자 위에
   얹히지만, headless Chrome + Malgun Gothic 조합에서는 **합성되지 않고 뒤로 밀려 나온다**
   (`0.2̇7̇` → `0.27˙`). → 은행 JSON 쪽에서 **인라인 마크업**(`position:relative` 컨테이너 + 절대배치 점)으로
   대체한다. 도구를 고치지 말고 콘텐츠에서 해결한다. 순환소수를 다루는 모든 학년·단원에 해당한다.
6. **병렬 배치 중에 검증 도구가 바뀌면 수치가 흔들린다.** 배치가 끝난 뒤 **전 단원 재검증**을 한 번 더 돌리고,
   그때 나온 값을 기록으로 남긴다.
7. ★ **JS 가 그리는 그림은 인쇄되지 않는다.** 원본 앱의 수직선·좌표축 중에는 눈금과 숫자를 스크립트로
   그려 넣는 것이 있다(`<g id="nl1ticks">`). 그대로 실으면 **눈금 없는 화살표만 남아 문제를 풀 수 없다.**
   → 눈금·라벨을 박아 넣은 **정적 SVG 로 다시 그린다.** 그림을 실을 때는 반드시 PDF 로 확인한다.
8. **태그 제거 정규식은 `<[a-zA-Z/!][^>]*>` 로 좁힌다.** `<[^>]+>` 는 부등식 `a < 0, b > 0` 의
   `< 0, b >` 를 태그로 오인해 먹는다 (실측: 24단원 중 1문항에서 정답이 `② $a 0$` 로 깨졌다).

### 8-1. 정답이 낱말인 문항의 함정 (실측)

정답이 `유한소수`·`순환소수`·`평행` 같은 **낱말**이면 V5(정답 누출 검사)가 오개념 카드 본문에서 그 낱말을 잡는다.
회피하려고 카드를 풀어 쓰게 되는데(`끝이 나는 소수`, `딱 떨어지나요`), **결과적으로 카드가 용어 암기가 아니라
현상을 묻게 되어 더 나아진다.** 제약을 그대로 받아들이는 편이 낫다.

짧은 수치 정답(`y = 1`)도 카드 예시 안에 우연히 포함되기 쉽다 → **카드 반례는 본문 문항과 다른 문자·수로** 만든다.

## 9. 검증 (`verify_bank.py`)

| 검사 | 내용 |
|---|---|
| V1 문항 수 | 은행 문항 수 == 원본 재추출 문항 수 |
| V2 정답 원자 | `answer_atoms` == 원본에서 재추출한 값 (**유형 안의 순번으로 대조**) |
| V3 합성 정답 | `answer_print` + `answer_unit` 안에 모든 원자가 있는가 (원자 `1` 은 생략 허용, KaTeX 는 걷어내고 비교) |
| V4 발문 규약 | `□`·앱 의존 표현 없음 / 요구문 있음 / `answer_format` 있음 |
| V5 오개념 | 태그가 카탈로그에 존재 / **카드에 정답 누출 없음** / 미사용 카드 경고 |
| V6 어투 | 학생에게 보이는 문구의 문어체(`~한다.`) 종결 검출 |

**`answer_atoms` 는 절대 손으로 고치지 않는다.** 원본과 다르면 원본이 옳다.

**대조 계약: 은행의 문항 순서 = 추출 순서.** V2 는 (유형번호, 유형 안 순번)으로 대조한다.
원본의 문항 번호를 키로 쓰면 안 된다 — 세대 A 의 `.q-num` 은 **난이도마다 1,2,3 으로 리셋**되어
L1·M1·H1 이 충돌한다(실측: 유형당 9문항이 3개로 뭉개져 전 단원 오탐). 순서를 바꿔 저작하지 말 것.

★ **경고 목록은 사람이 반드시 훑는다.** V3 는 원자가 전부 순수 숫자일 때만 엄격 판정이라,
**목록형·서술형 정답이 원본에서 틀린 경우는 오류가 아니라 경고로만 걸린다.**
실측: 이 방식으로 **원본 앱의 정답 오류 5건**을 잡았다(GCD 목록에 자기 자신 포함, 검산 과정을 답으로 표기,
`34 − 5 = 31`, 채점키가 해설과 불일치 등). 경고를 넘기면 그 오류가 그대로 종이에 실린다.

**경고는 판정 기준이 아니다.** 서술형·수식 답을 다시 쓴 경우(`내각합 = 360°. 일치함.` → `내각의 합 360°, 두 합은
서로 같아요.`)는 원리상 문자열이 달라진다. **오류 0 이 통과 기준이고, 경고는 사람이 눈으로 확인할 목록이다.**

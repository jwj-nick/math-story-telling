# 영상 제작 시스템 — 통합 계획

> 이 한 편으로 프로젝트 전체를 이해할 수 있다.
>
> **이 프로젝트는 영상을 양산하는 곳이 아니다. 영상을 잘 만드는 시스템 (프로세스 + 자동화) 을 구축하는 곳이다.** 절대 변하지 않는 목적은 → [`PURPOSE.md`](./PURPOSE.md)
>
> 작성: 2026-05-24 (시스템 구축 frame 으로 전면 재작성)

---

## 한 줄 요약

영상 제작의 6단계 (스토리보드 / 나레이션 / 이미지 / 모션 / 렌더 / 합성) 를 **수동 깊이 → 반복 적용 → 자동화** 의 3단계로 점진적으로 시스템화한다. 현재는 1단계 (수동 깊이) 의 출발점에 있다 — 1편 (에라토스테네스) 의 손작업 경험을 명시적 표준으로 정리하는 일.

---

# 1. 이 프로젝트의 정의

## 1.1 만드는 것

**영상 제작 시스템.** 다음 두 층:

1. **프로세스 층** — 6단계 각각의 표준 절차·도구·체크리스트
2. **자동화 층** — 표준화된 단계의 자동 실행 도구 (시간 ↓↓↓)

이 시스템이 잘 작동하면 영상 1편을 만드는 시간이 단계적으로 줄어든다:
- 1단계 (수동 깊이): 1편 약 60시간
- 2단계 (반복 적용): 1편 약 15시간
- 3단계 (자동화): 1편 약 3~5시간

## 1.2 시스템이 흡수해야 할 것

| 종류 | 무엇 |
|---|---|
| 6단계 절차 | 각 단계의 입력·출력·표준·도구 (`30_pipeline/` 의 6 sub-dir 가 1:1) |
| 도메인 표준 | 영상 1편의 길이·장면 수·이미지 수·SSML 패턴·모션 패턴 등 |
| 능력 (선택적 확장) | 핵심 시각화 30초 / 고급 음성 합성 / 배경음·효과음 / 인물 손그림 / 짧은 보조 영상 (§4) |
| 진화 원칙 | 다듬기 사이클 / 학습자 한 줄 / "양보하지 않은 것" 기록 등 (§5) |

## 1.3 부산물 (영상) 의 위치

본 시스템이 작동하면 그 결과로 영상이 만들어진다. 그 영상의 배포 위치는 본 프로젝트 외부:
- `../../50_channel/people/<인물>/<에피소드>/` (원본)
- `../../50_channel/seasons/<시즌>/<단원>/` (시청자 진입)

어떤 단원을 언제 만들지는 본 프로젝트의 결정이 아니다. **그건 math-story-telling 큰 그림 트랙의 결정**.

## 1.4 학습자(딸)에게 주는 값

본 시스템이 안정되면 학습자가 새 단원을 진행할 때 그 단원의 인물 영상이 짧은 시간에 만들어진다. 학습자는 "그 단원을 발견한 사람" 의 서사를 영상으로 접하면서 흥미를 얻는다.

영상이 학습자 학습 전체를 끌고 가지 않는다 — 그건 앱·문제 트랙의 책임. 영상은 **흥미 강화의 보조** 다 ("앱=백본 / 영상=보조").

## 1.5 만들지 않는 것

- 강의 톤 영상 (학원·교과서 스타일)
- 단원 내용 전부를 영상으로
- 자동화 욕심에 품질을 양보한 영상
- **산출물 수의 목표** ("N편 완성" 같은 표현)

# 2. 3단계 진화 모델

## 2.1 1단계 — 수동 깊이 (현재 위치)

**무엇**: 한 단원을 손으로 깊이 있게. 6단계 모두 직접 경험. 그 경험에서 표준 추출.

**현재 상태**: 1편 (에라토스테네스, 소인수분해) 의 결과물은 있다. 그러나 그 경험에서 추출한 표준 4가지 (§3.3) 가 아직 영상 표준 문서에 반영되지 않았다 — 즉 1단계가 절반쯤.

**1단계 완료 신호**:
- 1편의 모든 발견이 명시적 표준 문서에 들어감
- 6단계 각각의 `30_pipeline/<단계>/` 폴더에 "현재 표준 + 도구 + 함정" 이 정리됨
- 다른 단원을 빌드할 때 "어디서부터 시작해야 하는지" 가 분명함

**1단계 우선 작업**: §8 자율 작업 5건.

## 2.2 2단계 — 반복 적용

**무엇**: 1단계에서 만든 시스템으로 다음 단원을 빌드. 시스템 부족·격차 발견. 보강.

**입력**: 1단계의 표준 문서 + 도구 시드.
**출력**: 다음 단원의 영상 1편 + 시스템 격차 보고 + 보강된 표준.

**2단계 완료 신호**:
- 단원당 시간이 1편(60시간) 대비 1/4 (15시간) 이하
- 같은 시스템 격차가 두 번 발견되지 않음 (한 번 보강되면 그걸로 끝)
- 표준 문서의 변경 빈도가 낮아짐

**2단계 진행 방식**: 큰 그림 트랙이 "다음 단원" 을 진행할 때 그 단원으로 시스템 검증. 본 프로젝트가 단원을 선택하지 않는다.

## 2.3 3단계 — 자동화

**무엇**: 시스템이 안정. 단계별 자동화 도구 (`70_tools/`). 사람 손은 결정·창의 부분만.

**자동화 가능한 부분 (추정)**:
- 단원 메타 → 스토리보드 시드 자동 생성
- 스토리보드 → 나레이션 시드 자동 생성 (SSML 포함)
- 나레이션 → 음성 합성 (ElevenLabs API)
- 이미지 프롬프트 → Midjourney API 호출 (또는 가이드 출력)
- 모션 config 자동 생성
- 렌더·합성·표지 추출 (이미 자동)

**자동화 불가 (사람 손 영역)**:
- 인물의 본질·"한 단어" 결정
- 결정적 순간 (S4) 의 시각화 디자인
- 학습자 피드백 반영의 방향성

**3단계 완료 신호**:
- 1편 빌드 시 사람 시간 < 5시간
- "표준 변경" 이 거의 일어나지 않음
- 새 단원 진행 시 "또 똑같은 영상이 만들어진다" 가 아닌 "변주를 표현할 수 있는 시스템" 으로 인식됨

## 2.4 단계 간 신호 정리

| 신호 | 1→2 | 2→3 |
|---|---|---|
| 단원당 사람 시간 | 60h → 15h | 15h → 5h |
| 표준 변경 빈도 | 매 단원 | 분기당 1~2회 |
| 동일 격차 재발견 | 있음 | 없음 |
| 자동화 도구 수 | 0~2개 | 5개 이상 |

# 3. 시스템의 출발점 — 1편 (에라토스테네스)

본 시스템은 0에서 시작하지 않는다. 1편을 손으로 만들어본 경험이 있다.

## 3.2 1편의 한계 = 시스템이 흡수할 능력 발견점

이 1편을 그대로 반복하면 시스템이 작은 그릇이 된다. 한계:

1. **AI 이미지 5장 = 고품질 stock 사진 느낌.** 반복 시 "또 비슷한 풍경/인물 톤" 위험.
2. **음성의 다정한 어조 = 약 90% 만족** 이지만 결정적 순간 (S4) 의 감정 곡선은 평이.
3. **배경음·효과음 무음** → "영상이라기보단 슬라이드 + 나레이션".
4. **모션 = ken burns + fade 가 거의 전부.** 화면이 결국 정적.

이 한계들이 §4 의 "흡수할 능력" 으로 이어진다.

## 3.3 1편 경험에서 추출한 표준 4가지

1편 빌드 중에 발견되었으나 아직 영상 표준 문서 (`../../10_system/10_principles/STORY_VIDEO_v1_5.md`) 에 반영되지 않은 표준:

| 표준 | 무엇 | 위치 |
|---|---|---|
| **캐릭터 일관성 기법** | image_prompts.md 최상단에 공통 인물 묘사 분리. 모든 장면이 이 묘사를 상속 | `30_pipeline/3_image/` |
| **길이 사전 검증** | 본 합성 전 음성 1회 테스트 합성 → 길이 측정 → 95~120초 범위 검증 | `30_pipeline/2_narration/` |
| **인물별 음성 매핑** | 인물 각각의 음성 (성별·연령·톤) 표 결정. 매번 결정 X | `30_pipeline/2_narration/` |
| **산출물 디렉토리 이중 트리** | `people/<인물>/<에피소드>/` + `seasons/<시즌>/<단원>/` 동시 유지 | `../../50_channel/` |

이 4가지를 표준 문서에 반영하는 것이 **1단계 완료의 핵심** 이다. → §8 자율 작업.

# 4. 시스템이 흡수할 능력 5가지

1편의 천장 (§3.2) 을 넘어서기 위해 시스템이 단계적으로 흡수할 능력들.

**중요**: 이 5가지는 "특정 단원에만 적용" 이 아니라 **시스템이 흡수하는 능력**. 흡수되면 그 이후 모든 단원에서 사용 가능. 흡수 *순서* 와 *시점* 은 결정 항목 (§7).

## 4.1 핵심 시각화 30초

단원당 "꼭 봐야 하는 30초 1개". AI 이미지가 아니라 **JSXGraph / D3.js 동적 다이어그램**.

에라토스테네스 예시 — S4 30초:
막대기 + 그림자 각도 7.2° + 시에네 우물 + 지구 곡률 + 7.2° = 1/50바퀴 변환 + 둘레 풀려나오는 애니메이션.

"교과서·유튜브·다큐 다 안 보여주는 30초" 가 목표.

흡수 시 시스템 부담: 단원당 약 4~8시간 추가. JSXGraph 시각화 코드 작성.

## 4.2 고급 음성 합성

현재 edge-tts → **ElevenLabs**. 비용 차이가 아니라 **결정적 순간의 떨림·여운**.

흡수 시 시스템 변화:
- `30_pipeline/2_narration/` 에 ElevenLabs API 호출 단계 추가
- 인물별 voice 매핑 표 작성
- SSML 풀스펙 직접 활용

비용: 무료 quota 약 10000자 (단원당 600자 가정 시 16편 가능).

## 4.3 배경음 + 효과음

현재 무음. 흡수 시 영상 톤이 **"강의" → "다큐멘터리"**.

- **배경음** (BGM): 시대 팔레트마다 1곡 ambient. CC0 무료 출처.
- **효과음** (SFX): 결정적 순간 1회 sting.

흡수 시 시스템 변화:
- `30_pipeline/4_motion/` 또는 `6_final/` 에 음향 합성 단계 추가
- CC0 음원 라이브러리 관리

## 4.4 인물 손그림 외주

캐릭터 일관성 기법 (§3.3) 은 *동일성* 을 해결하지만 *품질* 은 해결하지 않는다.

흡수 시 시스템 변화: AI 이미지는 풍경·도구·환경, 인물만 사람 손그림. 외주 단가 추정 5~10만원/장.

이 능력은 **시스템 외부 자원 (외주)** 이라 자동화 불가. 1단계·2단계에서 사람 손이 들어가는 영역.

## 4.5 짧은 보조 영상

본 영상 (약 110초) 외 **30~60초 한 컷 영상**. 단원당 0~3개.

용도: 인스타·쇼츠 공유 / "학습자가 다시 보고 싶은 부분" 만 추출 / "인물의 한 단어 = 30초".

흡수 시 시스템 변화:
- 산출물 종류 +1
- 디렉토리 트리에 보조 영상 위치 정의
- 본 영상보다 만들기 쉬워서 자동화 친화적

## 4.6 흡수 우선순위

| 능력 | 1단계 도입 | 2단계 도입 | 3단계 도입 |
|---|---|---|---|
| 4.1 핵심 시각화 30초 | 실험 1회 (1편 S4 만) | 도입 | 자동 X (사람 디자인) |
| 4.2 고급 음성 합성 | 도입 | 안정 | API 자동 |
| 4.3 배경음 + 효과음 | 실험 1회 | 도입 | 음원 라이브러리 자동 |
| 4.4 인물 손그림 외주 | 검토 | 시범 1장 | 자동 X (외주) |
| 4.5 짧은 보조 영상 | 시스템 정의 | 도입 | 자동 친화 |

# 5. 시스템 진화 원칙 7가지

시스템이 단순히 "표준 + 자동화" 가 아니라 **진화하는 시스템** 이 되기 위한 운영 원칙.

### 원칙 1. 다듬기 사이클

매 단원 빌드 직후 "이 부분의 톤이 진짜 좋다" 한 곳을 찾고, 그것이 다음 단원의 표준으로 승격.

운영: 빌드 직후 회고 양식에 **"이번 단원의 다듬기 1건"** 필드. 그 다듬기가 표준 문서로 흡수되는 흐름이 시스템 진화의 일상적 동력.

### 원칙 2. 학습자 한 줄이 시스템을 재가공한다

학습자(딸)가 "7.2°가 부담" 이라고 하면 → **수정**이 아니라 **재가공**. 별도 30초 영상 추가, 직관 다이어그램 1개 추가.

운영: 학습자 피드백 (`.private/feedback/`) → 대화 기록 → 시스템에 짧은 보조 영상 (§4.5) 1편 추가.

### 원칙 3. Nick 손이 들어간 1건이 시리즈의 무게를 정한다

모든 산출물이 NCC가 만든 것이면 "AI 시리즈". 단원당 1건만 Nick이 쓴 글이 들어가면 "사람이 만든 시리즈".

본 시스템은 이 원칙과 약 교차 — Nick의 "에세이" 는 시스템 외부 (텍스트 deep-dive) 이지만, **본 시스템은 그 에세이가 영상에 한 줄 인용으로 들어갈 구조** 를 둔다.

### 원칙 4. 능력의 점진 흡수

5요소 (§4) 를 한꺼번에 흡수하지 않는다. 1단계 끝, 2단계 진입 시 1~2개씩 흡수. 시스템이 흔들리지 않게.

### 원칙 5. "한 단어" 압축

운영: 단원 메타 데이터 (`30_content/units/NN/meta.json`) 에 `한_단어` 필드 신설. 짧은 보조 영상 (§4.5) 중 하나가 이 단어 자체.

### 원칙 6. "양보하지 않은 것" 기록

매 단원 완성 시 Nick이 "이 단원에서 양보하지 않은 것" 한 줄을 기록한다. 모이면 "이 시리즈의 영혼" 문서.

### 원칙 7. 미완성을 의도한다 — 빈칸 5개

단원당 think-box 5개. 영상 외 자료에 적용 (deep-dive). 본 시스템은 짧은 보조 영상 (§4.5) 중 1개가 "질문으로 끝나는 30초" 일 수 있다는 약 교차.

## 가설 1 — 1편 표준이 다른 단원에 일반화되는가

**무엇**: 1단계에서 추출된 표준이 1편에만 적용되는 가정이 아니라 다른 인물·시대에도 일반화되는가.

- 격차 0~1건 → 1→2단계 신호 ✓
- 격차 2~4건 → 표준 보강 후 재검증
- 격차 5건 이상 → 1단계 표준 자체 재설계

**무엇**: §4.1 능력 흡수의 가치 검증. 영상에 "이거 진짜다" 순간이 만들어지는가.

**검증 방법**: 결정 ⑨ 실험 (1편 S4 30초만 동적 시각화 재제작). 학습자(딸) 1회 시청 → 반응 측정.

**판정**:
- 자발적 재시청 또는 "이거 더 알고 싶다" → 능력 흡수 가치 ✓
- 무반응 또는 "원래 영상과 비슷" → §4.1 폐기 또는 다른 시각화 방식

## 가설 3 — 음향 추가가 영상 톤을 격상시키는가

**무엇**: §4.3 능력 흡수의 가치 검증.

**검증 방법**: 결정 ⑩ 실험 (1편 기존 영상에 음향만 추가). 음향 유무 비교 청취.

**판정**:
- "확실히 다르다" → 시스템에 흡수
- "큰 차이 없다" → 효과음만, 배경음은 폐기

## 가설 4 — 시스템이 단계 진화 가능한가 (장기)

**무엇**: 3단계 진화 모델 (§2) 자체의 검증. 단원당 시간이 정말 60h → 15h → 5h 로 줄어드는가.

**검증 방법**: 각 단계 완료 시점에 단원당 시간 측정. `60_evaluation/` 누적.

**판정**: 시간이 안 줄어들면 시스템 설계 재검토.

# 1. 본 프로젝트의 본질

## 1.1 만드는 것

**new process — 영상 제작 시스템**. 다음 두 층:

1. **프로세스 층** — 6단계 (스토리보드 / 나레이션 / 이미지 / 모션 / 렌더 / 합성) 각각의 표준 절차·도구·체크리스트
2. **자동화 층** — 표준화된 단계의 자동 실행 도구

3단계 진화 (수동 깊이 → 반복 적용 → 자동화). 자세히는 [`PURPOSE.md`](./PURPOSE.md).

## 1.2 본 프로젝트는 양산하지 않는다

영상 산출물의 개수는 목표가 아니라 부산물. 결과적으로 챕터당 1~2편 영상이 만들어진다 — 시스템 작동의 *증거*.

## 1.3 학습자 (딸) 에게 주는 값

본 시스템이 안정되면 학습자가 새 단원 진행 시 그 단원의 인물 영상이 짧은 시간에 만들어진다. 영상은 **흥미 강화의 보조** — 앱·문제 트랙이 백본.

# 2. 작업 영역 — 외부 의존 0

## 2.1 본 프로젝트 안에서만 일한다

**본 프로젝트 (`11_video_gen_process/`) 의 작업 진행 중에는 외부 디렉토리를 변경하지 않는다.**

## 2.2 완성 후 외부로 이전 (덮어쓰기)

본 프로젝트가 충분히 안정되면 (완료 신호는 §10), 그 결과물을 외부의 다음 위치로 **덮어쓰며 이전** 한다:

| 본 프로젝트 산출물 | 외부 이전 위치 |
|---|---|
| 6단계 영상 표준 문서 | `../../10_system/10_principles/` (옛 `STORY_VIDEO_v1_5.md` 덮어쓰기 또는 대체) |
| 영상 빌드 스킬 | `../../10_system/30_skills/se_story_video_*/` (옛 skill 덮어쓰기 또는 대체) + mirror sync |
| 자동화 도구 (있다면) | `../../70_tools/` 또는 `../../10_system/30_skills/` |

이전 시점·방식은 본 프로젝트 진행 마지막 단계의 결정 (현 단계에선 추상적으로만 잡아둠).

## 2.3 외부 자료 = 참조 + 덮어쓰기 대상

§12 참조 자료 표 참조. 모든 외부 자료는 본 프로젝트에 대해 다음 둘 중 하나의 역할:

- **참조 자료**: 본 프로젝트 작업의 입력 (사실·맥락). 갱신 의무 X.
- **덮어쓰기 대상**: 본 프로젝트 완성 후 본 프로젝트의 산출물로 대체.

같은 파일이 둘 다일 수 있다 (예: 옛 표준 문서는 작업의 입력이자 마지막에 덮어쓸 대상).

# 3. 작업 진행 방식 — Q&A 연속

## 3.1 핵심 방식

**본 프로젝트의 작업은 NCC ↔ Nick 의 Q&A 연속** 이다. 답변이 다음 질문을 바꾼다.

- NCC 는 한 항목을 풀어 옵션·이유·영향을 정리 → Nick 응답
- 답변에 따라 다음 질문 자체가 달라질 수 있다 (미리 짜둔 질문 시퀀스 X)
- 한 결정이 굳어지면 §8 결정 누적에 기록
- 코딩·빌드는 결정 후에만 들어간다 (서두름 X)

## 3.2 도구 결정은 다양한 플랫폼 체득

ElevenLabs vs edge-tts, Midjourney vs DALL-E vs Stable Diffusion 같은 도구 선택은 "하나 고르고 끝" 이 아니라 **다양한 플랫폼 체험 → 장단점 체득** 이 본 시스템의 자산.

비교 결과는 단계별 표준 (`30_pipeline/<단계>/`) 에 누적 — 비교 표 + 선택 이유 + 미래 전환 조건.

## 3.3 step-by-step 첫 챕터부터

new process 의 정의를 **첫 챕터부터** step-by-step 으로 만든다. 한 챕터가 끝나면 다음 챕터.

여기서 "챕터" = new process 의 단위. 챕터 정의 자체가 첫 Q&A 의 주제 (§5).

# 4. New Process — 본 프로젝트가 자체 정의할 것

외부에 존재하는 1편 산출물 (`../../50_channel/season-1-ancient/unit-01/`) 은:

# 5. Step-by-Step 진행 계획 (큰 흐름)

본 프로젝트는 다음 큰 흐름으로 진행. 각 단계 안에서 Q&A 연속.

## 5.0 시스템의 단위 — agent·skill 조합

본 프로젝트가 만드는 "프로세스" 는 **agent·skill 조합** 으로 구현된다. 한 단계의 산출물 = "그 단계의 스킬 정의 + 그 스킬로 만든 첫 결과물 1건". 스킬 안에 프로세스·프롬프트가 내재화. (math-story-telling 의 기존 패턴 `/se_unit_plan`, `/se_story_write` 등과 일치)

각 단계의 진행 형태:
1. 스킬이 무엇을 하는지 (입력 / 출력 / 동작 / QnA / 리서치) 를 Q&A 로 정의
2. 스킬 명세 (SKILL.md 시드) 본 프로젝트 안에 작성
3. 스킬 실행으로 첫 결과물 1건 생성 (검증)
4. 스킬 정련 → 외부 이전 대비

## 5.1 단계 [정체성] (병행 진화)

영상이 무엇인가. 시청자·약속·길이·장면 구조·톤·시청 후 행동·시리즈 정체. 모든 단계의 상위 입력.

### 5.1.1 결정 완료 (2건)

- **결정 1 시청자** ✅ — 학습자 (중1 딸) + 광범 잠재 시청자 (채널 공개). 자세히는 §8 결정 1.
- **결정 2 약속** ✅ — 3겹: (1) 시대 감각 몰입 (2) 인물 정서 인상 (3) **발견의 필연성 서사**. 자세히는 §8 결정 2.

### 5.1.2 잔여 5건 — 자세한 질문 카드

각 항목 = (1) 무엇을 묻는가 / (2) 옵션 후보 / (3) NCC 잠정 추천 / (4) 영향 / (5) 트리거 시점.
결정 자체는 트리거 시점에 Q&A 로 확정하고 §8 결정으로 누적.

#### A3 길이 — 영상 1편의 표준 길이

**무엇을 묻나**
영상 1편이 몇 초인가. 고정인가, 가변인가, 챕터별 다른가.

**옵션 후보**
| 옵션 | 무엇 | 장단 |
|---|---|---|

**트리거 시점**: 영상 1 (스토리보드) 단계 진입 시 잠정 확정.

| 6. "양보하지 않은 것" 기록 | 매 단원 한 줄. 모이면 "시리즈의 영혼" |

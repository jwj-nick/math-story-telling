## 1. Step 개요

### 이 step이 무엇을 하는가

STEP 3 스토리보드는 STEP 2 가 만든 **스토리 시드** (장면 단위의 거친 설계: 시간 / 시각 단서 / 나레이션 시드 / 운반 약속 / 전환) 를 받아, 각 장면을 **정밀 카드** 로 변환한다. 한 장면 카드는 6 요소 — (1) 시각 (정밀) (2) 카메라 워크 (3) 텍스트 자막 (4) 나레이션 (5) 음향 (6) 전환 — 을 모두 못 박는다. 거기에 더해 전 영상에 걸친 **캐릭터 일관성 reference** 와 **시대 풍경 reference** 를 표로 고정한다. 스토리보드는 "장면이 화면에서 *어떻게 보이고 들리고 읽히는가*" 를 한 문서에 못 박아, 이후 4개 단계 (나레이션 / 이미지 / 모션 / 렌더) 가 각자 추측하지 않고 **같은 단일 소스를 읽도록** 만든다.

### 4축 중 어디에 기여

본 프로젝트의 영상 트랙은 1차적으로 **축 B (흥미 유발)**. 스토리보드는 결정 2 의 약속 3겹 (시대 감각 / 인물 정서 / 발견의 필연성 서사) 을 *장면별 화면*으로 번역하는 단계라, 흥미 유발의 그릇을 가장 직접적으로 빚는다. 동시에 S3 (소수의 체 격자 애니메이션) 처럼 **축 A (개념 이해)** 를 시각으로 운반하는 장면이 카드에 명시되며, S6 의 한 단어 압축 "정리" 처럼 **축 C (수학 언어 / 닻 단어)** 가 자막으로 고정된다.

### 8단계 파이프라인에서의 위치

```
[서사] → [스토리] → ★STEP 3 스토리보드★ → [나레이션] → [이미지] → [모션] → [렌더] → [합성]
            (선행)         (현 단계)          (후행 4단계가 본 카드를 직접 입력으로 소비)
```

선행 = STEP 2 `se-video-story` (스토리 시드). 후행 = STEP 4~7 의 **4개 단계가 모두** 스토리보드 한 문서를 입력으로 본다. 스토리보드는 파이프라인의 **분기점** — 한 줄기였던 스토리가 여기서 나레이션·이미지·모션이라는 4개 직렬·병렬 가닥으로 갈라진다.

### 이 step의 본질적 난제

1. **단일 소스로서의 정합성** — 스토리보드는 후속 4단계의 *공동* 입력이다. 자막 텍스트 (모션이 읽음), 자수 (나레이션이 읽음), 캐릭터 외형 (이미지가 읽음), 카메라 워크 (모션이 읽음) 가 한 문서 안에서 서로 모순되면 4단계가 각자 다른 영상을 만든다. 스토리보드의 본질적 난제는 **아직 만들지 않은 4개 산출물을 머릿속에서 동시에 동기화**하는 일이다.
2. **추상(스토리)과 구체(픽셀·초·dB) 사이의 번역** — 스토리 시드의 "남은 수 강조" 를 "17~22s, gold 강조, ding 효과음 3회" 로 못 박는 일. 너무 거칠면 후속 단계가 헤매고, 너무 이르게 못 박으면 (예: 픽셀 좌표) 후속 도구의 자유를 죽인다. *어느 해상도까지 결정하고 어디서 멈출지* 가 난제다.

## 2. Workflow (절차)

### 입력 align → 처리 → 출력의 단계별 흐름

스킬 동작은 SB1~SB7 7단계. exp-002 에서 실제로 밟은 순서:

| 단계 | 동작 | exp-002 실제 |
|---|---|---|
| **SB1** | 입력 align — 스토리 시드 §0 + 부록 A·B·C 확인, 정체성 (약속 3겹·톤) 확인 | `2-story-seed.md` 의 6장면 표 + 부록 C "스토리보드 신규 결정 항목" 4개 수신 |
| **SB2** | (필요 시) Q&A 보강 — 캐릭터 reference / 시대 풍경 / 자막 폰트 미정분 채움 | 캐릭터 = description 채택, 폰트 = 시리즈 표준 gold serif 채택 (Q&A 생략·NCC 직접 결정) |
| **SB3** | 캐릭터 일관성 reference 정리 — 인물별 외형 표 + 공유 인물 식별 | §0.1 표: 에라토 / 아르키메데스(등장 X) / 유클리드 / 류후이. 공유 인물 = 에라토 (S2·S4) → reference 우선 생성 표시 |
| **SB4** | 시대 풍경 reference 정리 — era 팔레트 hex + 자막 폰트·color + anachronism 체크 | §0.2: era-ancient 4색 hex + 도리아식 기둥 6개 + 죽간 + Noto Serif KR gold #E89B4F |
| **SB5** | 장면 카드 정밀화 — 각 장면 6 요소 못 박기 | S1~S6 6장면, 각 카드에 시각/카메라/자막/나레이션/음향/전환 6 sub-section |
| **SB6** | 자체 평가 + 다음 단계 입력 명세 — 부록 A·B·C·D | 부록 A (나레이션 자수·SSML) / B (이미지 8장·SVG 표시) / C (모션 카메라 워크) / D (한계) |
| **SB7** | 출력 — `<exp>/3-storyboard.md` | 11,365 bytes 작성 완료 |

### 실제 동작 순서 (시각화)

```
스토리 시드 (장면 거친 설계)
   │  SB1 align
   ▼
[정체성 못 → 약속 3겹 / 톤 A5 이야기톤 / 110초·550자]
   │  SB3·SB4  ← 전 영상 공통 reference 먼저 (캐릭터 + 시대 = "고정값")
   ▼
[장면 6장 × 6 요소 정밀화]  ← SB5 (장면별 루프)
   │  SB6  ← 4단계 입력으로 재포맷 (부록 A/B/C)
   ▼
3-storyboard.md  →→→  STEP4 / STEP5 / STEP6 / STEP7
```

### 의사결정 포인트 (분기)

- **캐릭터 reference 형식** (SB3): description 만 vs 참조 이미지. exp-002 = description (첫 단원이라 이미지 미존재). → STEP 5 에서 에라토 이미지 1장 생성 후 그것이 다음부터 reference 이미지가 됨.
- **장면 = SVG vs AI 이미지** (SB5/부록 B): S3 의 1~30 격자는 *수학적 정확성이 픽셀보다 중요* → SVG 가능 표시 (이미지 생성 비용·오류 회피). 인물·풍경은 AI 이미지.
- **이미지 재사용** (부록 B): S6 도서관 = S1 echo → 같은 이미지 재사용 (실제 6-motion-config.json 에서 S6 `img` = `4-S1-Museion.png` 로 확정됨).
- **카메라 워크 종류 수** (SB5): 다양성 (push in / pan / zoom / swipe / fade / ken burns 6종) vs 일관성 (4~5종 표준). retrospective 미결 항목.

### 다음 step의 입력으로 어떻게 연결되는가

스토리보드의 **부록 A·B·C 가 그대로 후속 3단계의 입력**이 된다. exp-002 가 이를 실증했다:

| 부록 | 후속 단계 | 실제 연결 증거 (exp-002) |
|---|---|---|
| 부록 A (장면별 자수 + SSML 권장) | STEP 4 나레이션 | `4-narration.*` 의 장면별 텍스트가 부록 A 자수 budget 을 따름 |
| 부록 B (장면별 이미지 수 + 공유 reference + SVG 표시) | STEP 5 이미지 | `5-images/` 의 파일명 (`4-S1-Museion.png` 등) 이 부록 B 의 장면-주체 매핑과 일치 |
| 부록 C (장면별 카메라 워크) | STEP 6 모션 | `6-motion-config.json` 의 `motion` 필드 (`push_in`/`zoom_out`/`ken_burns`/`pan_right`/`slow_zoom`)·scene id·자막 텍스트·자막 위치가 스토리보드 카드에서 직접 파생 |

특히 `6-motion-config.json` 은 스토리보드 카드의 **자막 텍스트를 그대로 재사용**한다 — "β", "베타 — 모든 분야 2등", "소수의 체", "아르키메데스의 편지", "인류, 같은 답에 두 번", "정리" 가 모두 SB5 카드 → motion caption 으로 흘렀다. 스토리보드의 자막 좌표 추상 ("화면 중앙", "하단") 이 모션에서 `x:"center", y:"0.45"` 같은 구체 좌표로 번역됐다.

## 6. 현재 구현 (exp-002 실제 사례)

### unit01 (에라토스테네스) 에서 실제로 어떻게 했는가

**6장면 카드 (요약표, `3-storyboard.md` §0):**

| S | 시간 | 시각 핵심 | 카메라 | 음향 | 자막 핵심 |
|---|---|---|---|---|---|
| S1 | 15s | 무세이온 외관 + 학자 실루엣 | 정적 → push in | 현악 fade in | (없음) |
| S2 | 15s | 에라토 클로즈업 | 정적 → zoom out | (계속) + 두루마리 | **β** + "베타" |

| S5 | 20s | 유클리드 → split → 류후이 | 정적 + swipe + 줌 아웃 | 동방 음색 미세 | "유클리드 BCE 300" / "류후이 CE 263" / "인류, 같은 답 두 번" |
| S6 | 15s | 도서관 echo + "정리" | 정적 + fade in/out | 클로징 톤 | **정리** (gold) + 부제 |

**S3 카드의 시간 phase 정밀화** (개념을 흥미로 운반한 핵심 장면) — 25초 안에서 격자 애니메이션을 초 단위로 못 박았다:

```
1~3s   책 분류하는 손
3~5s   손 → 수의 격자 (시각 메타포 전환)
```

**부록 A·B·C 입력 명세 (인용):**

- **부록 A (→ 나레이션)**: 장면별 자수 + 톤 강조 + SSML 권장. 예) `S3 | 120자 | 미세 긴장, 발견의 동기 | "소수의 체" 강조 + 페이즈 break`. 총 550자 (5자/s × 110s), ±10% 허용.

- **부록 C (→ 모션)**: 장면별 카메라 워크. `S4: pan up + pan over + zoom in (시러큐스로)`, 장면 간 전환 = cut (S2→S3) / fade (나머지).

**캐릭터 일관성 reference (§0.1, description 기반):**

| 인물 | 외형 description | 등장 장면 |
|---|---|---|
| 에라토스테네스 | 40~50대, 학자 풍모, 흰 chiton, 손에 두루마리, 진중한 표정 | S2, S4 |

→ "**에라토스테네스 reference 이미지 1장 우선 생성**" 표시가 STEP 5 의 첫 작업으로 못 박혔다 (S2·S4 공통 사용).

### 실제 겪은 시행착오·결정

- **외부 baseline 미참조** — 외부 의존 0 frame 을 지켜 옛 `storyboard_v1_5.md` 를 보지 않고 스토리 시드만으로 작성. 비교 검증은 다음 단원으로 미룸.
- **음향 = 잠정 명시만** — 배경음/효과음을 카드에 적되, 실제 mix·dB 는 STEP 8 합성으로 미룸 (적절한 분업으로 판정).
- **STEP 1·2 frame 3회 연속 적용** — frontmatter 5라운드 → 1 통검토 → 즉시 시범 → reverse-engineering → retro 패턴을 STEP 3 에서도 그대로 적용, 안정 작동 확인 (retro §1).

### 강점과 한계

**강점**: 부록 A·B·C 가 후속 3단계의 *직접* 입력으로 실증됨 (chain efficiency). 캐릭터 reference 양식 (description) 확립. 단일 문서로 4단계 동기화.

**한계** (retro §3):
1. **NCC 직접 동작** — 외부(타인) 호출 패턴 미검증.
2. **캐릭터 reference = description 만** — STEP 5 이미지 생성 시 시각 일관성 실증 필요 (description → 동일 얼굴이 실제로 나오는지).
3. **자막 자수 ±10% 검증 형식적** — SB5 글자수 검증이 눈대중.
4. **카메라 워크 6종** — 다양성 vs 일관성 trade-off 미결.

### 자동화·효율·품질 아이디어

- **부록 → 입력 변환 스크립트**: 부록 A·B·C 가 사람이 다시 읽어 변환되는 대신, 스토리보드에 *구조화 블록* (YAML front-matter 또는 fenced json) 을 심어 STEP 4/5/6 스킬이 기계적으로 파싱. 실제로 `6-motion-config.json` 이 스토리보드 카드를 손으로 옮긴 것이므로, 이 변환을 스토리보드 SB6 단계에서 *동시 생성* 하면 chain 손실 0.
- **anachronism 자동 체크리스트**: 시대 reference (§0.2) 의 의복·건축·도구를 표로 두고, 각 장면 시각 description 의 명사를 그 표와 대조해 시대 위반 (예: 종이 vs 두루마리, 인쇄 vs 필사) 을 SB4 에서 경고.
- **장면 카드 == 모션 config 미리보기**: 스토리보드 단계에서 timeline 막대 (S1 0~15s, S2 15~30s …) 를 ASCII/표로 그려, 자막 등장 타이밍이 나레이션 자수와 충돌하지 않는지 *그리기 전에* 확인.

## 8. 고급 Workflow (상상력·창의력)

### 스토리보드 = 후속 4단계의 단일 소스 (구조 설계)

스토리보드의 본질은 "한 번 적은 결정이 4곳으로 전파되는 단일 소스" 다. 이상적 구조는 **각 장면 카드를 4개 후속 단계가 *각자의 view* 로 읽는 한 행** 으로 설계하는 것:

```
                              ┌──────────────────────────── STEP4 나레이션 view (자수·SSML·화자)
한 장면 카드 (S3)             ├──────────────────────────── STEP5 이미지 view (주체·SVG여부·reference)
 ├ 시각 ─────────────────────┤
 ├ 카메라 ───────────────────┼──────────────────────────── STEP6 모션 view (motion enum·zoom·자막 timing)
 ├ 자막 (텍스트+좌표+timing) ─┤
 ├ 나레이션 (텍스트+자수) ────┤
 ├ 음향 ─────────────────────┴──────────────────────────── STEP8 합성 view (배경음·SFX·mix cue)
 └ 전환
```

고급형: 스토리보드를 **하나의 구조화 데이터 (장면 객체 배열)** 로 적고, 4개 단계 스킬이 각자 필요한 필드만 *projection* 한다. exp-002 의 `6-motion-config.json` 이 이미 이 객체 배열 (scenes[]) 형태인데, 스토리보드 단계에서 이 객체를 *최초로* 생성하고 STEP 4~7 이 필드를 채워 넣는 single-document-grows-through-pipeline 모델이 이상적이다.

### 시각-청각-텍스트 동기화 사전 설계

영상의 몰입은 세 채널 (보이는 것 / 들리는 것 / 읽히는 것) 의 *동시성*에서 온다. 스토리보드가 이를 *미리* 못 박는 고급 기법은 **3-track 동기 표** — 한 장면을 초 단위로 쪼개 세 채널을 한눈에:

| S3 시각 (보임) | S3 나레이션 (들림) | S3 자막 (읽힘) |
|---|---|---|
| 0~3s 책 분류 손 | "책을 분류하던 본능은 수에도 가닿았다." | (없음) |
| 5~10s 2(red)→배수 gray | "어떤 수는 더 못 나뉘고, 어떤 수는 나뉜다." | 격자 숫자 |
| 17~22s 남은 수 gold | "남는 수가 소수다." | (gold 강조) |
| 22~25s | (break) | **"소수의 체"** |

핵심 설계 규칙: **자막은 나레이션이 그 단어를 말하는 순간 ±0.5초 안에 뜬다.** exp-002 의 motion-config 에서 "소수의 체" 자막이 `65.0~73.0s` 에 뜨는데, 이는 S3 나레이션 끝부분 "남는 수가 소수다" 와 동기된 것 — 스토리보드 단계에서 이 동기를 *3-track 표로 미리* 설계하면 모션 단계의 timing 추측이 사라진다.

### 캐릭터 일관성·시대 정확성을 스토리보드에서 미리 보장하는 기법

- **캐릭터 시트 lock 먼저** — 영화 프로덕션의 *model sheet* 차용. 인물의 정면/측면/표정을 한 reference 로 고정한 뒤 모든 장면이 그 시트를 참조. 스토리보드 §0.1 이 이 역할인데, 고급형은 description 옆에 **불변 속성** (흰 chiton·두루마리·진중한 표정) 을 "캐릭터 DNA" 로 명시해 모든 등장 장면 프롬프트에 강제 주입.
- **시대 팔레트 + 금지 목록** — §0.2 의 era-ancient 4색 hex 옆에 **anachronism 금지 목록** (종이 X→두루마리·죽간 O, 안경 X, 인쇄 X, 아라비아 숫자 X→그리스 수기). 스토리보드가 시대 위반을 *생성 전에* 차단.
- **공유 자산 그래프** — 어느 이미지가 어느 장면에서 재사용되는지 (S6 = S1 도서관 재사용, exp-002 실증) 를 의존 그래프로 그려, 캐릭터·배경의 시각 일관성을 *재사용으로* 보장 (새로 생성하면 표류하므로).

### AI 멀티모달 스토리보드 자동화

- **멀티모달 미리보기** — 스토리보드 카드의 시각 description 으로 *저해상도 콘셉트 썸네일*을 즉석 생성해 카드 옆에 붙이면, 텍스트만으로 상상하던 화면을 시각 검토. 잘못된 구도를 스토리보드 단계 (가장 싼 단계) 에서 발견.
- **자수↔길이 시뮬레이션** — 나레이션 시드를 TTS 로 *드라이런* 합성해 실제 초를 측정, 스토리보드 시간표를 사전 보정 (exp-002 의 110초 설계 vs 140초 실측 gap 을 미리 잡음).
- **에이전트 라운드테이블** — 4개 후속 단계를 의인화한 4개 sub-agent (나레이터/아티스트/시네마토그래퍼/사운드) 가 스토리보드 초안을 동시에 읽고 "이 카드로 내 단계를 실행할 수 있는가?" 를 검토, 부족한 필드를 SB6 전에 역질의.

### 다른 도메인 차용 — 영화 콘티 / 애니메이션 X-sheet / 인터랙티브

- **영화 콘티 (storyboard)**: 샷 사이즈 (WS/MS/CU) 표기를 카드에 도입 — exp-002 의 "와이드 샷"(S1) / "클로즈업"(S2) 이 이미 이 어휘. 샷 사이즈를 enum 으로 표준화하면 이미지 프롬프트의 구도 지시가 정밀해진다.
- **애니메이션 X-sheet (노출표)**: 프레임 단위로 그림·대사·카메라·효과를 *세로 시간축* 에 정렬하는 표. 이것이 곧 위의 3-track 동기 표의 원형이다. 스토리보드를 X-sheet 양식으로 적으면 시각-청각-텍스트가 같은 시간 눈금에 강제 정렬된다 (`6-motion-config.json` 의 caption `start/end` 가 X-sheet 의 노출 칸에 해당).
- **인터랙티브 미디어 (게임 컷신 / 비주얼 노벨)**: "비트 (beat)" 단위 연출 — 한 장면 안의 감정 비트를 표시 (S3 = 호기심→발견→명명). 학습 영상에서는 이 비트가 *개념 이해의 단계* (분류 본능 → 체 방법 → 소수 정의) 와 겹쳐, 정서 비트와 인지 비트를 동시에 설계 가능.

### "이상적이라면 이렇게" 비전

스토리보드 한 문서를 적으면 → 4개 후속 단계의 입력 파일 (나레이션 jsonl / 이미지 프롬프트 md / 모션 config json) 이 *자동 파생* 되고 → 저해상 콘셉트 썸네일 + TTS 드라이런 길이 + anachronism 체크가 *그 자리에서* 붙어, Nick 은 스토리보드 한 장만 검토해 영상 전체를 승인/수정한다. 스토리보드가 영상의 *유일한 의사결정 지점* 이 되는 상태.

## 9. 고급 Contents 생성 방법 (품질 도약)

### 콘텐츠 자체의 질을 한 단계 올리는 구체 기법

- **개념을 *움직임*으로 운반** — S3 의 소수의 체 phase 표 (2 강조→배수 gray out→남은 수 gold) 는 정의를 *글이 아니라 시각적 소거 과정*으로 보여준다. 흥미를 잃은 중1 에게 "소수 = 더 못 나뉘는 수" 라는 문장보다, *지워지지 않고 살아남는 수*라는 **시각 서사**가 훨씬 강하다. 스토리보드 단계에서 모든 핵심 개념 장면에 "지워짐/살아남음, 모임/흩어짐" 같은 *동사적 메타포*를 1개씩 못 박는 것이 품질 도약점.
- **한 단어 닻 (축 C)** — S6 의 "정리" 가 자막 + 나레이션 + 부제 ("도서관 관장 = 분류 본능 = 소수의 체") 3중으로 못 박힌다. 인물 1인 = 1단어 (진화 원칙 5) 를 스토리보드가 *세 채널 동시* 로 각인.

### 학습 효과·몰입·정서 연결 강화

- **정서 비트와 인지 비트의 동시 설계** — 약속 2 (인물 정서) 가 exp-002 에서 S2 단일 장면에만 실려 약점으로 진단됐다 (story-seed 부록 A). 스토리보드 고급 기법은 *정서를 인지 장면에 스며들게* 하는 것 — S3 의 "베타(2등)라 불린 사람이 *남들이 안 본 분류에서* 자기 방법을 만든다" 처럼, 개념 장면의 카메라·자막에 인물 정서를 겹친다.
- **TONE_STRUCTURE dialog 분화 (v0.2 정련)** — 현 v0.1 스토리보드는 단일 나레이션 시드지만, TONE_STRUCTURE v3 는 **Q (존댓말 호기심) + A (친절 반말 설명)** 2화자 dialog 를 정한다. 스토리보드 v0.2 는 SB5 나레이션 시드를 **Q/A turn 으로 분리**하고 화면 인물 표시 (Q 자막/A 자막/양쪽) 를 결정해야 한다. 흥미를 잃은 학습자에게 *대화*는 독백보다 진입 장벽이 낮다. 예) S3 를 `Q: "근데 소수가 뭐예요?" / A: "잘 봐, 2의 배수를 다 지우고… 안 지워지고 남는 수!"` 로 분화하면 정서·인지가 한 turn 에 동시에 흐른다.

### 시리즈 정체성·일관성·확장성

- **시리즈 자막 표준** — gold serif (Noto Serif KR #E89B4F) + 화면 중앙 닻 단어 + 하단 부제. 이 양식이 모든 단원에 반복되면 시청자가 "이 채널의 영상" 임을 0.5초 안에 인식 (브랜드 identity). 스토리보드 §0.2 가 이 표준의 게이트.
- **시대 팔레트 = 시즌 색** — era-ancient (테라코타·황토·청동) 가 시즌 1 의 시각 정체. 시즌 2 (medieval) 진입 시 팔레트만 교체하면 같은 스토리보드 양식이 재사용 → 확장성.
- **재사용 자산 라이브러리** — S6=S1 재사용처럼, 시즌 안에서 도서관·풍경·소품 이미지를 자산 풀로 누적하면 단원당 신규 생성 이미지 수가 줄어 (진화 3단계 자동화의 씨앗).

### 이 step에서만 가능한 차별화 포인트

스토리보드는 **아직 아무것도 렌더되지 않은, 가장 싸게 고칠 수 있는 단계** 다. 여기서만 가능한 차별화:

1. **4채널 (시각·청각·텍스트·시간) 동기를 0원으로 설계** — 이미지 1장, 음성 1초도 안 만든 상태에서 동기 표 (§8) 로 전체 리듬을 잡는다. 모션·합성 단계에서 같은 수정을 하면 재렌더 비용이 든다.
2. **개념-정서-시대 3겹 약속을 장면별로 배분 검증** — story-seed 부록 A 의 약속 강도 표 (★) 를 스토리보드가 *장면 카드의 실제 6 요소* 로 검증. 약속 2 (정서) 가 1장면뿐이면 스토리보드 단계에서 다른 장면 자막·카메라에 정서를 보강.
3. **수학적 정확성을 SVG 로 격리** — S3 격자를 AI 이미지가 아닌 SVG 로 표시 (부록 B) 해, *개념 시각의 정확성* (배수가 정확히 지워지는가) 을 보장하면서 AI 이미지 오류 (잘못된 숫자 격자) 를 원천 차단. 학습 영상에서만 중요한, 스토리보드 단계의 결정적 품질 게이트.

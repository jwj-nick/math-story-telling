## 1. Step 개요

STEP 6은 STEP 5까지 만든 **정적 자원**(이미지 4~6장 + 나레이션 텍스트)을 **움직이는 영상의 설계도**로 바꾸는 단계다. 정지된 그림 한 장은 그 자체로는 시간이 없다. 여기서 우리는 각 그림에 **시간(언제부터 언제까지 화면에 머무는가)**, **카메라 운동(push in / zoom out / pan / ken burns)**, **자막의 등장·퇴장 타이밍**을 부여한다. 즉 STEP 6의 산출물 `6-motion-config.json`은 "이 그림을 18.23초 동안 1.0배에서 1.08배로 천천히 밀고 들어가라, 그동안 23.5초에 'β' 자막을 띄워라"라는 식의 **프레임 단위 연출 명세**다. 실제 픽셀은 STEP 7(렌더)이 FFmpeg `zoompan`으로 그려내지만, **무엇을 어떻게 움직일지의 결정**은 전부 이 단계에서 끝난다.

### 4축 기여
- **B. 흥미 유발 (주축)** — 모션은 "지루한 슬라이드쇼"와 "한 편의 짧은 다큐"를 가르는 결정적 차이다. 결정적 순간(S3 소수의 체, S5 "두 번 도달")에 카메라가 살아 있으면 감정이 실린다.
- **A. 개념 이해 (보조)** — S3 소수의 체처럼 자막 타이밍이 음성의 개념 설명과 정확히 맞물릴 때 이해가 강화된다.
- C·D는 본 단계에서 직접 다루지 않음.

### 8단계에서의 위치
```
03 스토리보드(부록 C 카메라 워크) ─┐
04 나레이션(scene별 음성 길이)   ─┼─→ [06 모션] → 07 렌더(zoompan) → 08 합성
05 이미지(5-images/*.png)        ─┘
```
STEP 6은 **세 입력(시각 단서·시간 예산·이미지 파일)이 처음으로 한자리에 모여 정합되는 합류 지점**이다.

### 본질적 난제
1. **음성-모션 동기화 (sync)** — 모션의 시간은 자유롭게 정할 수 없다. **이미 합성된 음성**(`4-narration.mp3`, 140.27초)이 시간의 절대 기준이다. scene 경계는 음성의 화제 전환점에 맞춰 고정되며, 모션은 그 칸 안에서만 움직여야 한다. 단 1초만 어긋나도 "말과 그림이 따로 노는" 영상이 된다.
2. **정적 입력으로 동적 인상 만들기** — 우리에게 있는 건 그림 1장씩이다. 영상 소스(촬영본)가 없다. 한 장의 그림에서 운동감을 짜내야 하므로 ken burns(서서히 확대/이동)가 거의 유일한 무기다. 이 좁은 도구로 6개 장면에 **각기 다른 정서**를 부여하는 것이 난제다.

## 2. Workflow (절차)

입력 align → scene별 시간 확정 → 모션 결정 → 자막 타이밍 배치 → config 출력의 5단계 흐름.

```
[1] 입력 align
    ├─ 03 부록 C 카메라 워크 (S1 push in / S2 zoom out / S3 ken burns / ...)
    ├─ 04 음성 길이 측정 (scene별 누적 초)  ← 시간의 절대 기준
    └─ 05 이미지 파일 경로 (5-images/*.png) + 캐릭터 reuse 맵

[2] scene별 시간 확정 (음성 sync)
    ├─ 합성된 mp3의 turn별 길이 + scene 경계 silence(1000ms) 누적
    ├─ scene 경계 타임코드 추출 → start/end 확정
    └─ 분기: 음성이 길어 한 이미지가 너무 오래 머무르면 → scene 분할(S5→S5a/S5b)

[3] 모션 결정 (scene 정서 → 카메라 언어)
    ├─ 도입/회귀 = push in·zoom in (빨려들기)
    ├─ 인물 소개 = zoom out (얼굴→맥락으로 물러나기)
    ├─ 발견의 과정 = ken burns (살아있는 응시)
    ├─ 공간 이동 = pan (지중해 건너 시러큐스로)
    └─ 병렬 인물 = slow zoom (정적·대등)

[4] 자막 타이밍 배치
    ├─ 03 스토리보드 자막 핵심 + 04 음성에서 그 단어가 발화되는 시점
    ├─ start = 발화 직전~직후, end = 다음 화제 전까지
    └─ 위치(x,y)·크기·색(gold=강조 / white=정보) 결정

[5] config 출력 (6-motion-config.json)
    └─ STEP 7 렌더가 그대로 읽는 기계 판독 JSON
```

### 의사결정 포인트 (분기)
| 분기 | 조건 | 선택 |
|---|---|---|
| scene 분할 | 한 이미지가 ~22초 이상 연속 | 이미지 2장으로 분할 (S5 → S5a 유클리드 / S5b 류후이) |
| 정적 vs 동적 | 자막·내부 애니메이션이 이미 정보를 운반 | 카메라는 약한 ken burns로 양보 (S3) |
| zoom 방향 | 도입·클로징 = 빨려들기 / 인물 등장 = 물러나기 | push_in vs zoom_out |
| 자막 색 | 개념·인물명 강조 vs 부가정보 | gold vs white |

### 3.4 외부 도구 + 선택 근거
- **FFmpeg `zoompan` (STEP 7 실행 도구)** — config의 zoom 배열·motion을 실제 프레임으로 렌더. INTEGRATED_PLAN §5.5.4의 GSAP/Lottie 후보 대신 **FFmpeg 단일 체인**을 시범 채택. 근거: 외부 의존 0(추가 런타임 불필요) + 이미지+음성 sync에 zoompan 한 도구로 충분 + 옛 v1.5의 HyperFrames(GSAP)보다 파이프라인이 가볍다. (00_index.md STEP 7 = "clips/ FFmpeg zoompan"으로 명시)
- **`ffprobe`** — MO2에서 mp3 길이·경계 측정. 시간의 절대 기준 추출용.
- 미래 전환 조건: 격자 애니메이션(S3 소수의 체 내부 강조)처럼 zoompan으로 표현 불가한 동적 도식이 필요해지면 Lottie/SVG 합성을 보조 도입.

## 5. Step Output (산출물)

### 5.1 산출 파일 형식 + 위치 규약
- **파일**: `40_experiments/exp-NNN-.../6-motion-config.json` (STEP 번호 prefix 규약 `6-`)
- **구조**: 전역 메타(`fps`, `resolution`, `total_duration`, `audio`, `font`, `palette`) + `scenes[]`(각 scene = id·img·start·end·motion·zoom·captions[]) + `transition`(fade in/out)
- **자막**: `captions[]` 각 항목 = text·x·y(상대좌표 0~1)·size·color(palette key)·start·end

### 5.2 다음 STEP 연결
STEP 7(렌더)이 이 JSON을 **그대로 기계 판독**한다:
- `img` + `zoom[0→1]` + `motion` → FFmpeg `zoompan` 필터 인자
- `captions[]` → `drawtext` 필터 체인(start/end = `enable='between(t,…)'`)
- `transition.fade` → 각 clip 시작/끝 `fade` 필터
- `concat`으로 clip 이어붙여 **길이 보존**(음성 sync 유지)

clips/ 디렉토리에 scene별 mp4(현재 S1.mp4 생성됨)가 떨어지고, STEP 8에서 `4-narration.mp3`와 합성된다.

### 5.3 품질 검증 기준
| 검증 | 자동(MO6) | Nick |
|---|---|---|
| 시간 정합 | Σ(end−start) = total_duration(140.27)? | — |
| 자막 경계 | 모든 caption.end ≤ 소속 scene.end? | — |
| sync 체감 | — | 음성 듣고 자막이 말과 맞는가 |
| 정서 적합 | — | 결정적 순간 모션이 감정을 살리는가 |
| 가독성 | y좌표 충돌 없는가(0.30/0.45/0.82 분리) | 자막이 얼굴/핵심을 가리지 않는가 |

## 6. 현재 구현 (exp-002 실제 사례)

### 6.1 6-motion-config.json 전역 설정
```
fps 25 / resolution 1280×720 / total_duration 140.27s
audio 4-narration.mp3 (Kanna+Kyle, STEP 4 확정 voice)
font NotoSerifCJKkr-Regular.otf (serif, 시대 무게)
palette gold #E89B4F(등대 화염, 강조) / white(정보) / shadow(외곽선)
```
주석이 핵심 원칙을 박아둠: **"scene별 시간 = 음성 sync 기준(scene 이미지는 다음 scene 음성 시작까지 표시)"**, **"concat으로 길이 보존(음성 sync)"**.

## 8. 고급 Workflow (상상력·창의력)

> 현재의 "손으로 정합한 정적 config"를 넘어 — **음성이 스스로 모션을 부르는** 데이터 기반 연출 파이프라인의 비전.

### 8.1 데이터 기반 자동 모션 — 음성 강세에 반응하는 카메라
지금은 NCC가 "S3는 ken_burns"라고 정한다. 이상적으로는 **음성 자체가 모션을 생성**한다.

```
4-narration.mp3
  ├─ ① 음성 분석: RMS 에너지(강세)·피치 곡선·발화 속도·무음 구간 추출 (librosa/ffmpeg)
  ├─ ② 강세 피크 = "강조 순간" → 그 프레임에 미세 push(±0.02 zoom 펄스)
  ├─ ③ 화제 전환(긴 무음 1000ms) = scene cut 자동 검출
  └─ ④ 의문문 끝올림(style 0.7) = 카메라 살짝 멈칫(zoom 정지) → 긴장
```
"인류, 같은 답에 두 번"을 발화하는 음성의 피치가 올라가는 순간, 카메라가 0.3초 동안 살짝 밀려 들어가도록 **음성→모션 매핑 함수**를 만든다. 비트(음악)에 맞춰 컷하는 뮤직비디오 편집 기법(beat-synced cut)을 **나레이션 운율에 맞춘 모션**으로 차용하는 것이다.

### 8.2 프레임 단위 음성-모션-자막 동기화
25fps에서 1프레임 = 40ms. 자막의 등장을 "초"가 아니라 **음소(phoneme) 단위**로 맞춘다. forced alignment(Whisper·MFA)로 "소수의 체"라는 단어의 **자음 'ㅅ'이 발화되는 정확한 프레임**을 찾아, 그 프레임에 자막을 keyframe-pop(0.12초 scale 1.0→1.15→1.0)으로 튀어나오게 한다. 말과 글자가 물리적으로 같은 순간에 태어나는 인상.

```
"소수의 체" 발화 = 1632프레임(65.28s)
  → caption 1630f fade-in 시작, 1632f scale-pop, 1635f 정착
  → 음성 '체' 끝(1700f) + 여운 200프레임 후 fade-out
```

### 8.3 카메라 언어 체계화 — "영화 문법"의 도입
모션을 6개 프리셋이 아니라 **문법 규칙**으로 격상한다. 영화·다큐·모션그래픽의 검증된 어휘를 차용:

| 차용 분야 | 기법 | 본 시스템 적용 |
|---|---|---|
| **다큐 카메라워크** (켄 번스) | 정지 사진에 느린 pan+zoom으로 "회상" 톤 | 역사 인물 영상 전체의 기본 어조 — 이미 ken_burns 차용 중. 더 느리게(0.6%/초). |
| **영화 편집 리듬** | scene 길이를 감정 곡선에 맞춤(긴장=짧은 컷, 사색=긴 호흡) | S3 발견=39.7초 긴 호흡(사색), 미래 단원의 클라이맥스=짧은 컷 누적 |
| **모션그래픽** | 키네틱 타이포그래피(글자가 의미대로 움직임) | "정리" = 흩어진 글자가 모여 정렬(인물 닻 시각화), "두 번" = 같은 자막이 두 번 깜빡 |
| **시선 유도** (composition) | 다음 컷의 피사체를 현재 컷의 시선 방향에 배치 | pan_right(S4 시러큐스)가 화면 오른쪽으로 시선을 끌고, 다음 scene 피사체를 우측에 |

### 8.4 키네틱 타이포그래피 — 자막을 "움직이는 의미"로
지금 자막은 떴다 사라진다. 고급 단계에서는 **자막이 개념을 연기**한다.
- **"소수의 체"** — 격자(1~30)에서 배수가 회색으로 지워지고(turn 15~19 음성과 동기) 소수만 gold로 남는 애니메이션. §6.5 한계 ②의 정면 돌파. 음성 "큰 수까지 줄 세우고, 배수를 차례로 지우는 거지"의 "지우는"에 맞춰 실제로 숫자가 지워진다.
- **"β"** — 2등을 뜻하는 베타가 1등(α) 옆에 살짝 작게, 그러나 빛나며 등장(인물의 정서적 아이러니 = 약속 2겹 인물 정서 인상).
- **"인류, 같은 답에 두 번"** — "두 번"이 글자 그대로 두 번 페이드.

### 8.5 이상적 파이프라인 비전
```
스토리 시드(정서 곡선) ─→ 음성(강세·무음·피치) ─→ [모션 엔진]
                                                  ├─ forced alignment(자막 프레임)
                                                  ├─ 강세→zoom 펄스
                                                  ├─ 정서 태그→카메라 문법
                                                  └─ 키네틱 타이포 keyframe
                                       ↓
                              motion-config.json (프레임 정밀)
                                       ↓
                              FFmpeg/Remotion 렌더
```
사람(Nick)은 "이 scene의 정서"라는 **한 단어**만 주고, 나머지 프레임 연출은 음성 데이터가 스스로 만든다. PURPOSE 3단계의 "자동화" 단계 = 사람 손은 결정·창의 부분만.

## 9. 고급 Contents 생성 방법 (품질 도약)

### 9.1 모션의 정서적 의미 — "결정적 순간 강조"
모션은 장식이 아니라 **감정의 운반체**다. 약속 3겹(시대 감각·인물 정서·발견의 필연성 서사)을 모션이 직접 운반하도록 설계한다.

| 약속 | 모션 표현 | exp-002 / 미래 |
|---|---|---|
| ① 시대 감각 | 도입 push_in으로 시청자를 시대 안으로 빨아들임 | S1 무세이온 push_in ✓ |
| ② 인물 정서 | zoom_out으로 얼굴에서 "베타"라는 운명으로 물러남 | S2 ✓ — 더: β 자막 미세 떨림 |
| ③ 발견의 필연성 | **결정적 순간에 카메라가 멈칫하거나 밀려 들어감** | S3 ken_burns(살아있는 응시), S5b "두 번 도달" 솟아오름 |

**핵심 원리**: 결정적 순간(S3 소수의 체, S5b 인류 두 번 도달, S6 한 단어 "정리")에는 모션·자막이 **동시에 정점**을 찍어야 한다. 카메라가 살짝 멈추고(주목), 자막이 가장 크게(S6 "정리" size 150) 뜨고, 음성이 강세를 준다 — 세 채널이 한 프레임에 수렴할 때 시청자의 감정이 봉인된다.

### 9.2 음성-모션-자막 프레임 단위 동기화 (몰입 강화)
중1 학습자는 **말과 그림이 어긋나면 즉시 산만해진다.** 반대로 정확히 맞물리면 "이해된다"는 느낌이 든다. 품질 도약의 핵심:
- 자막은 **음성보다 0.1~0.2초 먼저** 떠서 "들리기 직전에 보이게" → 읽기와 듣기가 겹쳐 강화.
- 개념어("소수의 체")는 음성이 그 단어를 말하는 **정확한 프레임**에 pop.
- 여운(S6 "정리")은 음성이 끝난 뒤에도 남아 **소화 시간**을 준다(A6 시청 후 행동 = 침묵·소화와 일관).

### 9.3 데이터 기반 자동 모션 (콘텐츠 질 + 확장성)
§8.1을 콘텐츠 관점에서: 음성 강세에 반응하는 모션은 **단원마다 다른 인물의 운율**을 자동 반영한다. 차분한 유클리드 scene은 잔잔하게, 흥분한 아르키메데스 등장은 톡 튀게 — **인물별 모션 개성**이 음성에서 자동으로 나온다. 손으로 매번 정하지 않아도 시리즈 인물 13명이 각자의 카메라 리듬을 갖는다(확장성).

### 9.4 카메라 언어 체계화 (시리즈 정체성)
§3.3 사전을 시리즈 표준으로 굳히면, 시청자는 학습 없이 **시각 문법**을 익힌다: "push_in = 새 시대 시작", "gold 자막 = 이 단원의 닻", "zoom_in 클로징 = 한 단어 정리". 13개 단원이 같은 카메라 문법을 쓰면 **채널 전체가 하나의 작품**으로 느껴진다(진화 원칙 6 "시리즈의 영혼").

### 9.5 키네틱 타이포그래피 (이 step만의 차별화)
"소수의 체"를 글자로 띄우는 것과, 격자에서 배수가 지워지고 소수가 남는 것을 **보여주는 것**은 학습 효과가 다르다. STEP 6은 **자막을 정적 라벨이 아니라 개념의 시연 도구**로 쓸 수 있는 유일한 단계다(STEP 5 이미지는 정지, STEP 8 합성은 음향). §7.1 능력 흡수(핵심 시각화 30초)와 결합하면 "단원당 꼭 봐야 하는 30초"가 바로 이 키네틱 타이포 구간이 된다.

### 9.6 영화 편집 리듬 / 다큐 카메라워크 / 모션그래픽 차용 (종합)
| 차용 | 본 시스템 적용 | 학습 효과 |
|---|---|---|
| **다큐 켄 번스** | 정지 그림에 회상 톤 부여 | 역사 인물의 "그때 거기" 몰입(약속 ①) |
| **영화 컷 리듬** | 발견 scene = 긴 호흡, 전환 = 짧은 컷 | 감정 곡선이 영상 구조에 새겨짐 |
| **모션그래픽 키네틱 타이포** | 개념어가 의미대로 움직임 | 추상 개념의 체화(약속 ③) |
| **뮤직비디오 beat-sync** | 음성 강세에 컷·zoom 동기 | 산만함 차단, "이해됨" 감각 |

**차별화 포인트**: 다른 교육 영상이 "그림 + 자막 + TTS"의 정적 합으로 멈출 때, 본 시스템의 STEP 6은 **음성 운율을 읽어 카메라와 자막을 살아 움직이게** 하여 "한 편의 짧은 다큐"의 격을 만든다. 이것이 모션 단계가 흥미(축 B)에 기여하는 가장 깊은 지점이며, 영상이 "흥미 강화의 보조"(INTEGRATED_PLAN §1.3)를 넘어 그 자체로 작은 작품이 되는 분기점이다.

## 3. 단원 완성 시 엔진에 손대는 곳 (3곳)

`app3/concept.js` 상단 `UNIT_READY` · `PLAY_READY` · (자산 있을 때만) `EXPLORE_READY`에 단원 번호를 `{1:1}` 형식으로 추가 → 사이드바 링크·놀이터 탭·탐험 탭이 켜진다. 미등록 단원은 사이드바에 회색(링크 없음)으로만 보인다. 허브 `index.html`은 `.unit.soon` 카드를 실카드(`<a class="unit" href="uN.html" data-u="uN">`)로 바꾼다. 엔진을 고쳤으면 캐시버전(`concept.css/js?v=`) bump — 앱 전체 한 값.

## 4. 답 형식 규약 (앱 확인 문제 · 연습 문제)

앱은 `MJ3.checkNum`(정수) 또는 `MJ3.check(id, test, out, opt)`(함수 판정)만 쓴다. 중3는 답이 √·분수·두 근·좌표인 경우가 많다.

| 답 종류 | 규약 | 예 |
|---|---|---|
| a√b 꼴 | 질문에 "(근호 안의 수만)" 또는 "(근호 앞 계수만)" 병기하고 숫자 하나만 입력 | 3√2 → "계수는?" 3 / "근호 안은?" 2 |
| 분수·삼각비 값 | `check(id, 0.5, out, {correct:'0.5'})` 처럼 **수 판정**으로 쓰면 `"1/2"`·`"0.5"` 둘 다 통과 — 엔진 `check`가 `a/b` 입력을 수로 읽음(`MJ3.num`, 파일럿에서 추가, v20260830b) | sin 30° → 0.5 |
| 이차방정식 두 근 | "작은 근" 또는 "두 근의 합/곱"으로 한 수만 묻기. 둘 다 필요하면 입력 2개(`c3`, `c4`) | x²−5x+6=0 → 작은 근 2 |
| 좌표·꼭짓점 | 입력 2개(x, y) 또는 "x좌표만" | 꼭짓점 (1, −3) |
| 부호 있는 답 | 입력은 ASCII `-` 그대로 받고 `check`가 `−`도 정규화(엔진이 이미 함) | −3 |
| 상관관계·분류·참/거짓 | 입력 대신 2~3지선다 버튼(`picks`/`pg-pbtn`) | 양/음/없음 |
| 무리수 근삿값 | 묻지 않음(계산기 영역). 대신 "√10은 어떤 두 정수 사이?" 처럼 정수 답 | 3과 4 → 3 |
| π·√ 표기(지면) | `answer_print`는 유니코드 √(U+221A)·²·− 사용, 분수는 `.frac` 마크업 | — |

## 5. 연습·프린트 규약 (파일럿에서 확정)

- p 페이지 = 7유형 × 3문항, 난이도 **L / M / M**((3)번에 "왜?" 박스). 은행 `level`도 같게. 유형 세트 `a/b/c`는 H 없음이라 전 문항 포함, `mock`은 `quota {L:1, M:1}` → 14문항.
- 회차 쪼개기: 7유형 → a(1·2·3) 9문항 / b(4·5) 6문항 / c(6·7) 6문항 / mock 14문항 = 회차 4개, PDF 8장.
- 낱말·근호 정답(유리수/무리수, √10, −2)은 `answer_print`에 근거를 괄호로 덧붙여 V5(카드 정답 누출)를 피한다. 오개념 카드는 단원당 10~13장.
- `answer_format`·`answer_unit`·`title`은 빌더가 이스케이프하므로 **HTML 금지, 유니코드(², √, −)만**. `stem_print`·`answer_print`·`hint`·`solution`·`principle`은 HTML 가능(`<sup>`, `.frac`).
- 프린트 허브 삽입 = `python 70_tools/print/hub_add_unit.py math3 N`(마커 기반, 재실행 안전). PDF는 `40_grades/middle/math3/print/uNN/`(미추적) + 배포 `mid3/print/uNN/`.
- 검증 = `70_tools/qa/check_page.py app3` → Node 정답 재계산 → 새 포트 서버 + headless Chrome 콘솔 0 → (파일럿만) iframe 하네스 → `verify_bank.py` 0 오류 → PDF 육안 2장.
